# Free Lunch for LLMs Confidence: The RL Critic Already Knows (2610.31820)
Status: concurrent (arXiv v1 2026-10-22, cs.CL, preprint only). Source: raw/ft/2610.31820.txt. Text basis: FULL TEXT.
Measured: confidence estimators for the policy's own responses: zero-shot verbalized probability, self-consistency (8 samples), R-Tuning (policy fine-tuned to append "I am sure" or "I am unsure"; score is the confidence-token probability), a linear probe on last-token activations "with the same labeled data", and the PPO critic (Sections 2, 4.1).
Models and benchmarks: Qwen3-8B and Nemotron-Cascade-8B, PPO-trained, thinking mode on (Appendix C); code ID is held-out TACO, CodeContests, and Codeforces; code OOD is LiveCodeBench; 4 samples per prompt; "rule-based grading" (Appendix C). Section 2 uses Llama-3-8B-Instruct on APPS-intro and TACO.
Findings: Table 3, code AUROC ID / OOD: Qwen3-8B Verbalized .60 / .61, R-Tuning .86 / .85, Probe .88 / .84, CaC .93 / .91; Nemotron Verbalized .58 / .60, R-Tuning .89 / .79, Probe .89 / .80, CaC .91 / .84. Table 1: external text-only estimators trained on the same (question, response, correctness) triples match self-estimation (APPS AUC self .84, Qwen-7B .82, Mistral-7B .86; TACO .89, .80, .90). R-Tuning lowers task accuracy on 15 of 16 splits (Section 4.2, Table 2), so its arm is scored on different generations from the probe arm.
Leaves open: within-problem scoring; prompt-only baseline; numeric trained stated confidence; identical generations across arms; base/instruct; reasoning toggle; explicit execution grading for code; no intervals in Table 3.
Breadth:
