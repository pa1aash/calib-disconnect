 Abstract 
 A deployed LLM agent emits tool calls, queries, and code that can be silently wrong—and by the time the
error surfaces, the action has already run. The frontier chat APIs these agents run on offer no reliable way
to tell which calls to trust. They hide the model’s own token probabilities. The agent’s stated confidence
barely beats chance on the mistakes that matter. And resampling does not help either, since frontier
models are now known to be highly repetitive, reproducing the same call across samples. 
 We recover the missing signal from a low-cost open-weight surrogate run in parallel. It reads the
same context, schema, and proposed action as the agent, then scores the call from its own 
log-probabilities through a family of complementary readouts. Teacher forcing and request-PMI 
(pointwise mutual information) weigh the likelihood of each argument value; a discriminative verdict 
judges the call as a whole; tool-choice competition tests the function against its siblings. One principle
tells an operator which to trust: a generative likelihood localizes wrong argument values , while the
verdict catches holistically wrong calls. When the error type is unknown, an ensemble over the family is the
low-regret default—a light logistic combiner, matched by a simple orientation-corrected average. The whole
readout is training-free, needs no access to the agent’s internals, and costs one prefill pass in parallel
with the tool call. 
 This proxy ranks correct calls above wrong ones more reliably than either signal a black-box operator
has today. Its edge over an agent’s stated confidence is largest exactly where it matters most: on
confident mistakes. On difficult coding tasks it reaches AUROC 0.825 0.825 where the actor’s own stated
confidence is near chance ( 0.598 0.598 ), and the generative readouts improve on stated confidence by + 0.07 +0.07 to
 + 0.28 +0.28 across the three additional actors we audit. Against self-consistency it gains + 0.14 +0.14 to + 0.19 +0.19 on
near-deterministic actors, at 1 / K 1/K the cost of resampling. The signal then drives two deployment modes. A real-time
gate escalates an agent’s least-trustworthy calls for human review ( + 0.05 +0.05 to + 0.30 +0.30 accepted-action
accuracy at 50 % 50\% coverage). And confidence feedback returns the tool result together with the
score, so the agent adjusts its own next step; this lifts end-to-end task success on live-execution
benchmarks ( + 0.119 +0.119 and + 0.137 +0.137 , both p ≤ 10 − 4 p{\leq}10^{-4} ) and beats a random-value control where step
errors are silent ( + 0.078 +0.078 , p = 0.003 p{=}0.003 ). 
 1 Introduction 
 Consider a customer-service or data agent running on a frontier chat API. It issues a refund tool call, a
database query, or a block of Python. If that action is silently wrong, the cost lands downstream, after
execution. The operator would like a confidence signal to gate the action—but in this, the common 
deployment setting, the two signals a deployer would reach for are both unavailable. (i) The most direct
signal, the actor’s own token log-probabilities, is hidden by the frontier chat APIs agents run on. (ii) The
standard black-box substitute is self-consistency : resample the actor K K times and measure
agreement. It collapses here, because frontier agents are near-deterministic . The actor re-emits the
identical call on the overwhelming majority of inputs, leaving almost no sample variance to read—and it
costs K K frontier generations to find that out (§ 4 ). The actor’s own verbalized
self-assessment, meanwhile, is least reliable exactly on its confident mistakes. If we cannot read the actor’s
probabilities and it cannot detect its own errors, where should a confidence signal come from? 
 Our answer is a proxy log-probability. A small, open-weight, log-probability-capable model runs as
a training-free sidecar (Figure  1 ): it reads the same ( context , schema , proposed action ) (\text{context},\text{schema},\text{proposed action}) the actor conditioned on—no gradient access, no fine-tuning, no actor internals,
no shared weights—and emits a scalar confidence. That confidence ranks action correctness
better than either black-box baseline (§ 4 ). Its edge over the actor’s self-assessment is
largest exactly on the actor’s confident mistakes, such as hard code it cannot self-verify. And it
significantly beats self-consistency in the near-deterministic regime deployed agents occupy, at 1 / K 1/K the
cost of resampling a frontier model. Because the auditor is a smaller open model its work is a
 prefill —one forward pass over the already-known action, no autoregressive decode—making it a
lightweight, actor-agnostic plug-in for any framework. Cost, latency, and the fail-open guarantee are in
§ 8 . 
 The signal is not monolithic. Which readout to trust has predictable structure , and that structure is
what makes the sidecar both cheap and targetable. Every proxy readout is one of two types: a
 generative likelihood (teacher forcing, or request-PMI, which discounts values the scorer finds likely
 regardless of the request) or a discriminative decision (a YES/NO verdict, tool-choice
competition). This one distinction predicts two things. (a)  Which failure mode a readout catches : a
generative likelihood reads wrong argument values , tracking judge-free per-parameter accuracy where
the verdict is blind to it, while the verdict reads holistic wrongness (§ 5 ).
(b)  Whether a small scorer suffices : teacher forcing is access -bound, equivalence-tested
against a scorer twice its size, whereas the verdict is capability -bound and improves with scale
(§ 6 ). Because the readout type localizes the error, inspecting which readout fires does
more than rank reliability—it tells an operator what to look at, turning a scalar into a first diagnosis of
the likely failure mode. Even the safe-default fusion can be decomposed into its per-type readouts for that
diagnosis. We study function-calling and code agents: their actions are the consequential, error-prone
decisions in deployed systems, and their correctness is checkable from the call, context, and schema. 
 We show that such a sidecar beats the two baselines a black-box deployer would otherwise reach for
(§ 4 ). Read as a reliability ranking , a small open-weight auditor’s log-probability
out-predicts both the actor’s verbalized self-assessment and its self-consistency, and it does so across
three actor families. The beats-self margin is regime-graded: the verdict wins in the holistic
regime, the generative TF/PMI in argument-value regimes. We then put
the readout-type framework to work (§ 5 , 6 ). Because which single readout wins
depends on the call’s error locus, an orientation-corrected fusion of the family is the lowest-regret default
when that locus is unknown—as it is in deployment. A learned combiner does no better than a simple oriented
average. 
 Finally, we evidence two deployment modes end-to-end (§ 7 ). The ranking drives selective
prediction on every dataset, needing only an escalation channel. And returning the score to the agent
alongside the tool result lifts end-to-end task success on two live-execution benchmarks, beating a
random-value control where step errors are silent—a distinction an unannotated control alone would have
missed. Throughout, claims are regime-graded and scoped to that class of actions. 
 2 Background and related work 
 Confidence estimation for LLMs differs mainly in the source of the signal. Every existing
source is unavailable or unreliable once the actor is a deployed, black-box, near-deterministic agent.
 Actor-internal probabilities. P(True)/self-evaluation reads the model’s probability on its
 own answer  ( Kadavath et al., 2022 ) —intra-model, and inaccessible behind a frontier chat API.
 Actor verbalized confidence asks the model to state a number  ( Lin et al., 2022 ; Tian et al., 2023 ; Xiong et al., 2024 ) ; it is reliable only where the model is well-calibrated, and least reliable
exactly on its confident errors. Actor sampling/agreement —self-consistency  ( Wang et al., 2023 ) ,
SelfCheckGPT  ( Manakul et al., 2023 ) , semantic entropy  ( Kuhn et al., 2023 ; Farquhar et al., 2024 ) —needs multiple actor samples and collapses under the near-determinism of deployed frontier agents
(§ 4 ). All three read the actor ; none survives the black-box, near-deterministic regime. 
 A second model as the signal source. LLM-as-judge  ( Zheng et al., 2023 ) and
cross-examination  ( Cohen et al., 2023 ) bring in another model but read its words —a verbalized
verdict; weak-to-strong generalization  ( Burns et al., 2024 ) and learned process/outcome
verifiers  ( Lightman et al., 2024 ) require a training step; guardrail
classifiers  ( Inan et al., 2023 ) screen content, not action correctness.
 Cross-model likelihood as a metric. Scoring text by a second model’s token
log-probabilities is established in generation metrics: BARTScore casts evaluation as generation and
reads a scorer model’s likelihood  ( Yuan et al., 2021 ) , GPTScore steers the same quantity by a
natural-language instruction  ( Fu et al., 2024 ) , while learned MT metrics instead regress on human
judgments  ( Rei et al., 2020 ) ; probability-curvature tests read likelihood geometry to detect
machine-generated text  ( Mitchell et al., 2023 ; Bao et al., 2024 ) . All of these score
 prose —its fluency, factuality, or provenance—never whether a tool call will execute
correctly . And none is organized by which failure mode the readout catches. Our request-PMI readout follows the
domain-conditional-PMI correction introduced against surface-form competition in answer
scoring  ( Holtzman et al., 2021 ) , reweighting a likelihood by its context-free prior. Calibration and oversight. Post-hoc calibration sharpens
a classifier’s own probabilities  ( Guo et al., 2017 ) , presuming the access we lack; monitoring an
untrusted model with a weaker trusted one is the control-protocol setting  ( Greenblatt et al., 2024 ) , to
which we contribute a concrete training-free monitor signal.
We build on standard deployment machinery rather than claim it: accept-if-passes execution-feedback
repair  ( Chen et al., 2024b ; Chen et al., 2023 ; Ni et al., 2023 ) (self-correction has known limits without an
external check  ( Huang et al., 2024 ) ), selective prediction /
risk–coverage  ( El-Yaniv and Wiener, 2010 ; Geifman and El-Yaniv, 2017 ) , and cost-driven
cascades  ( Chen et al., 2024a ) , which our two deployment modes instantiate.
 The gap we fill: inference-time, training-free, black-box-compatible action verification
from a second model’s log-probabilities—not its words, not the actor’s own—organized by a failure-mode
map over generative/discriminative readout types. 
 3 The proxy-confidence sidecar 
 Figure 1: The proxy-confidence sidecar: a training-free plug-in hook. The sidecar (dashed) taps the
agent’s tool-call hook, reads only ( context , schema , action ) (\text{context},\text{schema},\text{action}) —no logits, weights, or
fine-tuning—and emits a confidence c c , scored in parallel with tool execution. Drawn here are the two
in-loop modes: a real-time oversight gate (Mode A: high c c commit, low c c escalate to a human) and
 confidence feedback (Mode B: return the tool result together with c c to the actor, which chooses its
next move). Details in § 7 –§ 8 .

 scorer ) reads only ( context , tool schema , o ) (\text{context},\text{tool schema},o) — the same information the actor
conditioned on —and computes a scalar confidence (Table  1 ) at temperature  0 0 . Our primary

large open-weight model of different lineage than the actor, to rule out same-family self-preference bias;

 Two primitives. 
 Every readout is one of two types, and this distinction organizes the paper. A
 generative readout scores the likelihood the auditor assigns to the action, either raw (teacher
forcing, TF) or request-contrasted (request pointwise mutual information, request-PMI). The contrast matters
because raw likelihood rewards generic argument values: PMI subtracts the same value’s log-probability with
the request withheld , keeping only the evidence the request supplies. A
 discriminative readout is instead the auditor’s
 posterior over a discrete label set —over correctness (the verdict) or over function identity
(tool-choice competition). The type predicts both the failure mode a signal catches (§ 5 )
and whether a small scorer suffices (§ 6 ); Table  1 lists the four instances.
The verdict needs only generated-token log-probabilities (any chat API that exposes them), whereas TF/PMI
require prefill/echo access. We elicit the verdict two ways and report which throughout.
 Generated-token elicitation reads the log-probability of the scorer’s own next token after the “is
this correct?” prompt. Matched elicitation instead forces YES and NO and renormalizes over the pair;
because that is the same mechanism as teacher forcing, it is confound-free when we compare the verdict
against the generative signals. The two mostly agree, diverging where free-form generation carries
formatting cues the forced pair strips out. The divergence is sharpest on xLAM: there the generated-token
verdict ties the actor while the matched verdict is near-chance, so the xLAM claim rests on TF/PMI rather
than the verdict.

signal out-predicts the baseline), and lowercase “ p p ” is a frequentist test p p -value. 2 2

 4 The sidecar beats the deployer’s two baselines 
 The deployer’s two black-box options both fail in the deployment regime, and the proxy signal beats each.
 (1) vs. the actor’s self-assessment. Every proxy readout (§ 3 ) reads the scorer’s

is decidable by reading them (§ 9 )—precisely the regime a deployer cares about.

 8 Deploying the sidecar: cost, latency, and the safe default 
 Why the sidecar is cheap: the scorer’s work is a prefill. 
 The confidence readouts are dominated
by prefill , not autoregressive decode. Teacher-forcing the actor’s already-known action needs
one forward pass over known tokens with zero generation; request-PMI needs two; the verdict needs one
prefill plus a single token. The scorer never pays the long decode the actor already paid, so a 14 14 B pass
over the shared context is cheaper than the actor’s own generation—and than the K K frontier generations SC
needs. “Lightweight” here means per-call compute; the sidecar is still a second model to host. A
generative-only deployment is cheapest, since a 14 14 B suffices for the access-bound signals, while a
verdict/fusion gate provisions the 32 32 B (§ 6 ).
 Measured on the deployed 14 14 B fp8 sidecar at realistic full-context length (one L40S GPU,
Table  9 ), a scored call takes 123 123 – 159 159  ms at the median ( p ​ 99 ≤ 179 p99{\leq}179  ms). That is a
single-digit-percent addition to the
 100 100 s-of-ms a real tool call (DB query, API round-trip) already costs, and it is hidden entirely when the
scorer runs concurrently with execution. Scoring is triggered by the framework’s pre-execution tool-call hook,
which already holds the ( context , schema , action ) (\text{context},\text{schema},\text{action}) tuple, so it needs no extra actor
calls , adds ≈ 0 {\approx}0 to the Mode A critical path, and fails open on timeout so the guardrail can never
stall the agent. Because the hook fires per call, scoring can be restricted to high-stakes calls: as a design
policy (not a measured cost-saving) a static allowlist of writes/refunds/deletes plus a free-form-argument
heuristic routes argument-bearing calls to TF/PMI. The evidenced selectivity is that the signal tells
you where to spend a fixed review budget once calls are scored (§ 7 ).

 The failure-mode map
(§ 5 ) says which single signal wins in each regime. But exploiting it requires
knowing the error locus a priori , which is exactly the deployment knowledge a black-box operator
usually lacks. Worse, every single signal has a catastrophic regime . The verdict is near-blind

coarse holistic calls the verdict handles best (BFCL v3 0.549 0.549 vs. the 0.714 0.714 optimum there). Committing
to either one blind therefore risks a large loss. We quantify this as worst-case regret : the AUROC
gap between a fixed policy and the best-achievable signal in each regime. Reading the oriented fusion caps
worst-case regret at 0.019 \mathbf{0.019} AUROC (mean

Table  4 , App.  B ). 
 Fusion or a single signal? A practitioner’s rule. 
 The choice is risk management , not
performance maximization: default to oriented fusion whenever you cannot predict, per call, where the error
will be—the common black-box case. Fusion is not the highest- ceiling readout in any regime but the
lowest- floor one, the only choice independent of the call pattern. Drop to a single signal only when you know the error locus a
priori: a verdict for holistic correctness, teacher-forcing / request-PMI when argument
 values carry the risk, tool-choice competition for wrong- function routing. Each is
cheaper, and ties or edges fusion where you are right about the locus. The deployable edge
tracks the actor’s error rate. It is largest on error-prone tool/code regimes (AppWorld + 0.11 +0.11 , BFCL,
NESTFUL, miss_param), and slightly negative only for the verdict on easy xLAM ( − 0.06 -0.06 , where TF/PMI still
lead)—exactly the calls the actor already gets right, which least need a guardrail. 
 9 Limitations and scope 
 Our claims are scoped to actions whose correctness is decidable by reading them—for a tool call,
whether it matches the request and schema. Where the deciding evidence is an external fact absent from the
context, we claim nothing. One hazard carries into deployment: a readout’s sign is regime-dependent.
Teacher forcing anti-correlates with correctness wherever the fluent completion is the wrong one
(§ 5 ), so orientation must be fit on held-out labels per regime and never ported; an
unvalidated sign gives an anti-correlated gate, not merely a weak one. The beats-self edge is
regime/family-graded, not universal—on BFCL outside family A
the verdict only ties (§ 4 )—and a second strong closed frontier family is
untested. The cost claim rests on a 1 / K 1/K -generations plus smaller-model argument and single-GPU latency
(Table  9 ); multi-tenant serving is unprofiled and scorer size spans only a 2 × 2\times ratio
( ≤ \leq 8B untested). Learned fusion does
 not beat an orientation-corrected rank-average (App.  D ), so we claim no trained
calibrator. Finally, Mode B is regime-dependent: it beats a random-value control only where step errors are
silent (§ 7 ), so it warrants a scorer-validity check Mode A does not.

 Appendix J Feeding the signal back to the actor (self-review detail) 
 Beyond selective escalation (Mode A) and confidence feedback (Mode B), we tested handing the actor its own
proxy confidence to self-correct . The protocol keeps the actor black-box: it completes its trajectory;
the Qwen3-32B auditor scores every call; the actor is then shown its calls annotated with per-call signals
and re-emits a corrected sequence. Arms differ only in the annotation: blind (none),
 verdict / tf / fusion / all , and placebo . The placebo shows the same
numbers deranged onto the wrong calls—identical flag budget, wrong positions—which makes it the decisive
control: it separates localized information from a mere look-again nudge. 
 The boundary is whether the actor can self-verify the call at review time (Table  11 ).
Take single-shot xLAM first, where correctness is legible only from the schema. There, showing the signal
beats unaided review on the A1 reviewer (Holm p = 0.004 p{=}0.004 vs. blind), and beats the deranged placebo on
both reviewers (A1 p = 0.013 p{=}0.013 , A2 p = 0.006 p{=}0.006 ). The gain is therefore localized information rather
than a look-again nudge. On A2 the vs-blind margin is directional but not significant after correction.
NESTFUL (recompute) and live BFCL-v4 (re-read real tool output) go the other way: unaided review already
captures the gain, and no signal arm beats blind or placebo. These negatives share one cause, and it is the
boundary itself—when the actor can cheaply self-verify the call from the real result, a proxy number adds
little beyond unaided reflection. The same boundary separates our two inline benchmarks below. 
 Mode B in full: the readouts in a live loop. Detail behind § 7 ’s Mode B—appending
each step’s confidence to its real tool result, so the actor sees it in context on every observation and may
adjust its next action. We compare the readouts of § 5 
against three controls: an unannotated run, a vigilance arm that announces the audit but shows no
number, and a random arm that shows an independent U ⁡ ( 0 , 1 ) U(0,1) draw in place of the real confidence
(Table  10 ). 
 On InterCode nl2bash   [ Yang et al., 2023 ] the readouts order as § 5 predicts. All arms cover the same 193 usable tasks (200 minus 7 whose gold command fails
its own grader) and every contrast is paired. Announcing an audit without showing a number does nothing
( 0.389 0.389 , − 0.010 -0.010 , p = 0.87 p{=}0.87 ), so any effect requires the number itself. The discriminative verdict alone
does not separate ( 0.430 0.430 , + 0.031 +0.031 , p = 0.36 p{=}0.36 ). The generative likelihoods do: request-PMI reaches 0.472 0.472 
( + 0.073 +0.073 , 25/11, p = 0.029 p{=}0.029 ) and teacher forcing 0.497 0.497 ( + 0.098 +0.098 , 25/6, p = 0.001 p{=}0.001 ). Strongest is the
oriented fusion at 0.518 0.518 ( + 0.119 +0.119 , 29 rescues vs. 6 regressions, exact p = 10 − 4 p{=}10^{-4} , bootstrap
95% CI [ + 0.062 , + 0.176 ] [{+}0.062,{+}0.176] ). The generative-over-discriminative ordering and the fusion’s low-regret
behaviour were both established offline as ranking properties (§ 5 , § 6 ); here
they reappear in a live loop. Read against the random arm below, only the generative readouts and their
fusion clear its 0.440 0.440 —the verdict arm ( 0.430 0.430 ) does not reach it. The separation that survives a noise
control is therefore specifically the generative one. 
 On nl2bash the random arm rules out the trivial explanation that any number in the loop makes the actor more careful:
an independent U ⁡ ( 0 , 1 ) U(0,1) draw does not significantly beat the unannotated control ( 0.440 0.440 , + 0.041 +0.041 , 25/17,
 p = 0.28 p{=}0.28 ), and fusion beats it by + 0.078 +0.078 (19/4, p = 0.003 p{=}0.003 , CI [ + 0.031 , + 0.124 ] [{+}0.031,{+}0.124] ). A meaningless
scalar is therefore not sufficient: the annotation’s content matters relative to noise. We state the claim at
that level deliberately. The real and random streams differ in more than one respect—in where their low
values fall, and in how they are scaled. (Fusion occupies a narrow band, mean 0.636 0.636 , sd 0.144 0.144 , while the
uniform draw has twice the spread and dips below 0.10 0.10 on 9 % 9\% of steps.) The comparison therefore does not
by itself identify which property drives the effect, so we report the end-to-end result and leave the causal
decomposition to future work. 
 AppWorld test_challenge (417 tasks, 139 scenarios) shows the opposite pattern, and the contrast is
the point. Inline fusion gains + 0.137 +0.137 over the unannotated control there ( 100 100 / 43 43 , p < 10 − 4 p{<}10^{-4} ). But so
does the random arm, by + 0.132 +0.132 ( 95 95 / 40 40 , p < 10 − 4 p{<}10^{-4} ), and the two are indistinguishable
( + 0.005 +0.005 , 46 46 / 44 44 , p = 0.92 p{=}0.92 ; cluster-robust 95% CI [ − 0.043 , + 0.053 ] [{-}0.043,{+}0.053] , and + 0.008 +0.008 , p = 0.81 p{=}0.81 , on
the 390 tasks where our step cap forced neither label). On that benchmark any scalar suffices: we detect no
contribution from the readout’s content. Reporting only the vs-control number would have made AppWorld look
like a second confirmation; the random arm shows it is not one. 
 What distinguishes nl2bash is the shape of its failures: its answers are md5 sums, counts and
file listings, so a subtly wrong pipeline returns a well-formed, plausible, wrong value. Classifying every
executed step of the benchmark’s published reference trajectories ( n = 1176 n{=}1176 ), 50 % 50\% of wrong steps
are silent —clean, non-empty output with no error text—and 48 % 48\% of episodes contain at least
one such step (a proxy for our actor’s error profile rather than a direct measurement of it). There is no
traceback for a reviewer to restate, so an external judge adds information the actor cannot obtain from its
own observation. (Our unannotated control scores 0.399 0.399 , below the 0.485 0.485 the benchmark reports for its own published reference actor.
Two harness choices account for the gap. The first is an 8-turn cap per task. The second is rewriting
leading- cd compound commands as subshells, to work around a path-handling bug in the environment
that prevents the working directory from persisting. Both apply identically to every arm, so they depress
absolute success uniformly and leave the paired contrasts unaffected.) 
 The two benchmarks also differ in the signal’s measured validity, in the same direction. On AppWorld the
 displayed inline confidence has no task-level validity on this split (AUROC 0.388 0.388 mean-pooled,
 0.474 0.474 min-pooled—at or below chance, and below a trajectory-length baseline at 0.608 0.608 ), against 0.64 0.64 
on nl2bash . This is a different quantity from the AppWorld verdict of Table  3 
( 0.894 0.894 ): that is a per-call verdict AUROC on the standard split, whereas this is the task-level pooled
validity of the displayed fusion on test_challenge under the revised scorer prompt. The per-call
readout retains its ranking power; what fails is its aggregation to a task-level target on this split. The
reason is structural: AppWorld steps execute Python whose failures mostly raise , so the diagnostic
information is already in the observation the actor reads. A scorer-prompt revision that removed a measured
position artifact there (confidence–step-index correlation + 0.60 → + 0.15 +0.60\rightarrow+0.15 , reaching parity between
mandatory setup steps and substantive actions) succeeded mechanically yet bought zero predictive
power. That locates the failure in the target rather than the prompt. The operational reading is this: the
readout’s content earns its cost only where the environment does not already surface its own errors.
An inline number may still raise accuracy elsewhere, as it does on AppWorld, but then any scalar would do.
A random-value arm is what tells an operator which case they are in. 
 Taken together, Mode B raises end-to-end accuracy on both live-execution benchmarks ( + 0.119 +0.119 and
