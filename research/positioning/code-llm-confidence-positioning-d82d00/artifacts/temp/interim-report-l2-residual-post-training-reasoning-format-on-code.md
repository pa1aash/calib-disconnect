# Interim report: l2-residual-post-training-reasoning-format-on-code

**Locus question:** Where the probe-verbal disconnect arises on code (base vs instruct, post-training stage, reasoning on vs off, elicitation format) and whether trained or recalibrated verbal confidence closes it; decides the L2 residual under A21 and the A14 pivot.
**Flavor:** dialectical

## What the corpus already said

The vault already holds the whole evidential base for this locus; I fetched no new paper (the one arXiv HTML fetch, Kumaran 2603.17839, returned "URL already fetched" and only added a backlink). Ribeiro et al. [[on-llms-internal-representation-of-code-correctness]] occupies probe-beats-verbal on four instruct 7-8B models at whole-solution granularity (Sec 4.2.1; Sec 5.2.2: reflective ranking "often doing worse than Random"), with zero-shot verbal readouts, accuracy-based metrics only, and no base, reasoning, or causal factor (searched in the note body: "base model" 1 hit in Sec 6, "reasoning model" only as a citation). The corpus splits the remaining L2 questions into two camps. Side A (a general-NLP direction transfers to code): [[gpt-4-technical-report]] Fig 8 (post-training hurts token-logprob calibration on MMLU), [[reasoning-models-better-express-their-confidence]] (reasoning better in 33 of 36 settings), [[open-the-oyster-empirical-evaluation-and-improvement-of-code-reasoning-confidenc]] (code reasoning, verbal only). Side B (readout-specific, may differ on code): [[mechanistic-interpretability-of-code-correctness-in-llms-via-sparse-autoencoders]], [[closing-the-confidence-faithfulness-gap-in-large-language-models]], [[do-large-language-models-know-what-they-are-capable-of]], [[characterizing-overconfident-failure-in-llm-based-code-generation-full-text]]. Treat the Campos-with-probe attribution as a mislabel.

## What the new sources say

No new fetches. I re-read these vault full texts for section-level evidence (all full text unless marked).

**Rathnasuriya and Yang, 2610.11300** [[characterizing-overconfident-failure-in-llm-based-code-generation-full-text]]. Sec 3.1: four instruct 7-8B models; "For the post-training analysis in Section 5.5, we additionally compare base and instruction-tuned variants of OpenCoder and DeepSeekCoder." Sec 5.5 (MBPP+): OpenCoder failing-program confidence rises "from 0.8685 to 0.9224", entropy falls 0.4754 to 0.2401, "Confidence AUC changes from 0.5230 to 0.5094, with ΔAUC = −0.0136 and a 95% confidence interval of [−0.0911, 0.0652]." DeepSeekCoder: base confidence AUC 0.4391 (certainty anti-aligned with correctness), instruct 0.5654, ΔAUC +0.1263, CI [0.0447, 0.2089]. Authors' finding: "post-training can increase confidence in incorrect code independently of the reliability of uncertainty as a correctness signal." Sec 6.1, Table 5: Platt cuts Brier (CodeLlama 0.459 to 0.248) while BSS stays about 0.001. Token-level only; no verbal, no probe (Sec 7 effective-rank is exploratory). This is the only code base-vs-instruct comparison with execution labels in the vault, and its direction is not uniform.

**Tahimic and Cheng, 2510.02917** [[mechanistic-interpretability-of-code-correctness-in-llms-via-sparse-autoencoders]]. Sec 5.5: "GemmaScope SAEs were trained exclusively on the base model... yet SAE-derived directions retain their effectiveness in the instruction-tuned model"; feature L19-5441 F1 0.821 (base) vs 0.772 (instruct); MBPP pass rate 29.9% to 38.4%; steering correction 4.04% base vs 2.93% instruct. Gemma-2-2b only, MBPP only, no verbal or sampled readout, no calibration metric. Its causal work (steering fixes 4.04% of errors, corrupts 14.66% of correct code; orthogonalizing correct directions causes 83.62% corruption vs 18.97% control; Sec 5 and Fig 8) acts on code output correctness, not on stated confidence, so it does not locate where information is lost between state and report.

**Campos, Klassert, Ulges, 2611.07876** [[which-signals-of-code-correctness-survive-distribution-shift-hidden-state-and-ca]]. Sec V-A: gpt-oss-20b is a reasoning model but "we prefill its final channel so that it also answers directly... reasoning would cost about 1,100 generated tokens per candidate." Sec VIII (construct validity): medium-effort reasoning raises gpt-oss balanced accuracy "from 62.4% to 67.8% and the AUROC of its Yes probability from 0.68 to 0.73, still below the trained internal methods (Table IV)." So a reasoning toggle exists for the output-confidence readout only; the probe was never read under reasoning. No verbal numeric confidence. Abstract: predictors transfer between benchmarks "largely by identifying problems on which the model tends to fail. However, their ability to rank candidates within the same problem is limited." Table II column layout is garbled in the vault copy; I did not rely on its cell values.

**Robustness of the internal representation, 2608.08266** [[on-the-robustness-of-llms-internal-representation-of-code-correctness]]. Abstract: "no single configuration is best, and that isolating the fault does not help." Table II (BigCodeBench, PCA/last-token rows): fitting on concept framing but validating on neutral framing gives 36-48% accuracy, concept/concept gives 56-63%, and directions fit out of distribution on the synthetic set fall to 13-33%. It varies the probe's extraction framing only; no verbal readout varied.

**Tuerlings and Valdenegro-Toro, UncertaiNLP 2026** [[verbalized-uncertainty-in-coding-llms-contamination-aware-calibration-uncertainl]]. Table 1 (365 LiveCodeBench v6 problems, six instruct coder models, three verbal formats on frozen generations): Qwen-32B AUROC 0.834 / 0.810 / 0.841 (Direct / CoT / Linguistic); DS-33B 0.760 / 0.675 / 0.638; DS-6.7B 0.518 / 0.716 / 0.498; CL-7B Linguistic ECE 0.013 with AUROC 0.491. "ECE and AUROC measure different properties and do not correlate across cells." Eight of 18 cells collapsed. This occupies elicitation format as a factor within verbal readouts on code, and shows verbal discrimination is scale-dependent (not uniformly near chance), which weakens a blanket "verbal is disconnected" story.

**Barkan, Black, Sourbut, 2512.24661** [[do-large-language-models-know-what-they-are-capable-of]]. Abstract: "reasoning LLMs perform comparably to or worse than non-reasoning LLMs." Fig. caption (Exp. 3 and 1): reasoning settings toggled within models ("(0) and (4k)... 0 and 4096 reasoning token budgets, (none) and (med.)"); AUROC step-1 vs after-the-fact; "Reasoning models perform comparably to or worse than non-reasoning models." BigCodeBench and SWE-bench Verified, but in-advance (pre-attempt) verbal confidence, so it is not a post-hoc confidence on a produced solution.

**Wang et al., Open the Oyster, 2511.02197** [[open-the-oyster-empirical-evaluation-and-improvement-of-code-reasoning-confidenc]]. Sec 5.1.2: DeepSeek-Reasoner beats DeepSeek-Chat on all metrics (CRUXEval-I ECE 0.045, BS 0.018, PS 0.376). Tasks are REval and CRUXEval (code reasoning: output, coverage, state prediction), not code generation graded by tests; DeepSeek-Reasoner vs Chat differ in more than the reasoning toggle (different post-training), a confound the paper does not control.

**Wang et al., RLCM, 2604.23333** [[process-supervision-of-confidence-margin-for-calibrated-llm-reasoning]]. Table 1, LiveCodeBench column (DeepSeek-R1-Distill-Qwen-7B, trained on math only): RLCM probe-read confidence ECE 0.051, GRPO probe 0.130, RLCR verbal 0.218, C2GSPG logits 0.499. A reasoning model on code with a probe-read vs trained-verbal comparison, but the confidence mechanisms differ in training as well as readout, only ECE and PCE are reported in the table, and the accuracy is average rollout pass@1. This is the nearest code instance of "probe-read beats trained verbal with reasoning on", and it is ECE-only.

## Evidence synthesis

The record shows a clean empirical split by readout family, not a single "post-training hurts / reasoning helps" story. On token probability, code is the one place with direct base-vs-instruct data, and it does not reproduce the GPT-4-report sign: instruction tuning raised failing-program confidence in both models, but changed discrimination by -0.0136 (CI includes 0) in OpenCoder and by +0.1263 (CI excludes 0) in DeepSeekCoder, where the base model's confidence was anti-aligned with correctness (AUC 0.4391). On verbal confidence the NLP literature points both ways: Tian et al. say RLHF verbal beats token probability; RLCR says RLVR collapses verbal AUROC to 0.50 and 0.47; Yoon et al. and Zeng et al. say reasoning-style training improves verbal calibration; Barkan et al. (BigCodeBench, SWE-bench, in-advance) and Miao and Ungar (joint solve-and-rate inverts the direction) say it does not or can hurt. On code, nothing in the vault runs a base model's verbal readout at all, and Ghosh et al. show why: a 7B base model emitted two verbal labels and the pre-registered guard excluded it.

On the probe side the direction is more consistent in NLP and less consistent on code. In NLP the probe reads internal correctness better than the verbal channel in base models (Miao and Ungar Sec 3.1, 3.3) and in reasoning models (Probe-SD Table 1), and training the verbal channel can close most of the discrimination gap (Probe-SD Table 2; RLCR Table 1) while recalibration cannot (Verbal-Iso AUROC unchanged; Rathnasuriya Table 5 BSS about 0.001). On code the probe advantage is narrower than the Ribeiro headline suggests: it is a selection-accuracy win on 7-8B instruct models, probe accuracy depends on the framing used to fit it (2608.08266 Table II), the advantage over output confidence flips with benchmark shift for gpt-oss (2611.07876 abstract), within-problem ranking is limited, a prompt-length-only baseline already reaches AUC 0.657 (2606.14530), and a diffusion-code-model study finds no consistent probe advantage over log-probability (Heckler Table 1). Verbal confidence on code is not uniformly at chance either: Qwen-32B reaches AUROC 0.84 under all three formats (Tuerlings Table 1).

The structure that emerges for A21 and A14 is this. Each of the three L2 factors (tuning stage, reasoning, format) has some general-NLP precedent but with a contested sign, and at least one concrete code-specific mechanism that the NLP result cannot transfer across: (i) code base models can have anti-aligned token confidence (DeepSeekCoder base AUC 0.4391), which inverts the GPT-4-report narrative that tuning corrupts a once-calibrated base; (ii) joint code-plus-confidence generation is an operational obstacle (Zeng Limitations) and the "reasoning contamination" result (Miao and Ungar Sec 3.4) predicts joint prompts degrade verbal discrimination; (iii) code correctness is dominated by between-problem difficulty and prompt properties, so any readout can score well without within-problem skill. Training or recalibration closing the discrimination gap (A14 criterion 3) is established in NLP only for training, and on code only as ECE evidence (RLCM LiveCodeBench column); no code study reports discrimination after training stated confidence against a probe.

### Position A: the general-NLP direction transfers, so the L2 residual is only a model/benchmark change (OCCUPIED, A21 clause 2)

Strongest case: three of the four named factors have a published NLP direction with decent breadth. Post-training damages token calibration (GPT-4 report Fig 8; Qwen-RL pre-CoT AUROC 0.320, Table 1 of the post-training paper; RLVR verbal AUROC 0.47-0.50 in RLCR Table 1). Reasoning improves verbal calibration (Yoon: 33 of 36 settings; Open the Oyster: ECE 0.045 on CRUXEval-I) and probes beat verbal in reasoning models (Probe-SD Table 1, 24 of 24 comparisons). Format sensitivity is shown on code (Tuerlings) and across channels in NLP (Ghosh). Where the gap sits is answered in NLP (base models already have it: Miao and Ungar Sec 3.1, 3.3), and training closes it (Probe-SD Table 2, RLCR Table 1, ConfTuner). Under A21 clause 2, a factor with an established NLP direction and no stated code reason is OCCUPIED, and Ribeiro plus Campos plus Rathnasuriya plus Tuerlings could be read as an A20 union.

### Position B: a concrete residual survives (NARROW)

Strongest case: the union fails on its own terms. No fetched work puts a probe and a verbal readout on the same code generations with a base model or a reasoning-on condition (Ribeiro: all instruct, no reasoning; Campos: reasoning prefilled off; Rathnasuriya: token-level only; Tuerlings: verbal-only, no probe; SAE: no verbal). The NLP direction is not established but contested: Tian et al. versus the GPT-4 report on post-training; Yoon versus Barkan versus Miao and Ungar on reasoning; Rathnasuriya's DeepSeekCoder sign flip on code. Each factor has a stated code reason (anti-aligned base confidence; joint-output obstacle and reasoning contamination; between-problem confounding). The A21 clause 1 test (factor, not a change of models) is met by all three factors. Training-closes-the-gap has no code instance with discrimination metrics.

## Committed position

Position B is better supported, but only for two of the three factors and only as a factorial decomposition, not as a headline. The load-bearing reason is that the supposed general-NLP direction is not established (Tian versus the GPT-4 report on post-training, Yoon versus Barkan and Miao and Ungar on reasoning) and Rathnasuriya Sec 5.5 already shows a code-specific sign that NLP would not predict (DeepSeekCoder base token-confidence AUC 0.4391 rising to 0.5654 after tuning, ΔAUC +0.1263, CI [0.0447, 0.2089]), while no fetched work crosses probe, verbal, and sampling readouts with base/instruct pairs or a reasoning toggle on the same code generations. That makes tuning stage x readout and reasoning toggle x readout NARROW, not OCCUPIED, and it means pivot criteria 1, 2, and 4 are not triggered by the vault. I am less confident about elicitation format as a standalone residual: Tuerlings Table 1 occupies format effects within verbal readouts on code and Ghosh occupies cross-channel format effects outside code, so format survives only as an interaction (does the probe-minus-verbal gap change with format), and it should be a controlled nuisance factor, not a claimed finding. Pivot criterion 3 (A14) is the live threat, not a trigger: training the verbal channel closes most of the discrimination gap in NLP (Probe-SD AUROC .825 to .928 vs probe .948; RLCR .69 vs RLVR+Probe .55), recalibration provably does not (monotone maps leave AUROC fixed; Verbal-Iso unchanged, Rathnasuriya BSS about 0.001), and the one code data point (RLCM LiveCodeBench ECE 0.051 vs RLCR verbal 0.218) is ECE-only. Prescriptive design consequences: (1) a defensible L2 spine needs at least one trained-verbal arm (a Probe-SD-style distillation or an equivalent SFT of the stated-confidence channel) plus an isotonic-verbal control reported in AUROC, because without it a reviewer can cite Probe-SD and RLCR to say the gap closes; (2) base models need a base-compatible readout (P(True)-style yes/no token probability or few-shot numeric with a ≥3-distinct-values guard, per Ghosh's H3 failure) or the base-vs-instruct comparison is undefined for verbal; (3) the reasoning toggle must be the same weights (for example Qwen3 thinking on/off), not DeepSeek-Reasoner vs Chat as in Open the Oyster, with the probe read at a fixed position (prompt-final and answer-boundary) and a prompt-length residualization control (2606.14530: 0.881 to 0.842 versus a 0.657 baseline); (4) report within-problem and between-problem discrimination separately (Campos), since the probe edge may be difficulty detection; (5) at least three base/instruct pairs from different families, with AUROC differences judged by problem-clustered paired bootstrap (Rathnasuriya's own CI on ΔAUC is [-0.0911, 0.0652] for OpenCoder, so n of about 400+ problems per cell is the realistic floor to resolve effects near 0.05).

- **Position:** The L2 residual after Ribeiro is NARROW and survives A21 as a code-grounded decomposition of where the probe-verbal discrimination gap opens (tuning stage and reasoning toggle), but it cannot carry a paper unless it includes a trained-verbal arm and an isotonic-verbal control, because NLP already shows that training closes most of the gap.
- **Confidence:** medium (about 65%). High on "no fetched work crosses the factors on code"; lower on whether TMLR reviewers will accept the code-specific reasons as sufficient under A21.
- **Boundary conditions:** Holds for 7-30B open-weight models, Python function-level generation with execution labels, probes trained on the same model's hidden states. It does not extend to repository-level agents (L4 territory), nor to closed models without hidden-state access. The "CLEAN (provisional)" parts hold only until a full-text search over the 2026 preprints is possible.
- **What would change this position:** (a) a fetched record showing a base-instruct-by-readout code study with execution labels (would make Q2 base OCCUPIED); (b) a code study showing trained stated confidence reaches probe AUROC within about 0.03 on execution labels (would trigger pivot criterion 3 and demote L2 to analysis); (c) evidence that the DeepSeekCoder sign flip is a one-model artifact (a third base/instruct pair showing a uniform sign, which would remove the code-specific reason); (d) a same-weights reasoning on/off code study with probe and verbal readouts.
- **Evidence weight:** Three code studies bear directly (Rathnasuriya Sec 5.5, Campos Sec V-A/VIII, Tuerlings Table 1), each missing a key readout; two code studies bear partially (Barkan, Open the Oyster); one code ECE-only training result (RLCM); about seven NLP studies set the direction priors (Miao and Ungar, Probe-SD, RLCR, Yoon, Zeng, Tian, GPT-4 report), with conflicting signs on post-training and reasoning; two code probe papers weaken the probe-beats-verbal premise (Heckler, 2606.14530 length baseline).
