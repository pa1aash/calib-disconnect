# Interim report: probe-advantage-real-or-difficulty-confound-on-code

**Locus question:** Whether the probe-over-own-readout advantage on code survives supervision-matched readouts, input-only baselines, and within-problem discrimination; decides whether L2's headline is robust or an artifact.
**Flavor:** dialectical

Scope note. Section and table citations below come from vault full texts. The one new fetch is Bulut (arXiv 2609.03436), a primary-source chase from [[disentangling-task-difficulty-from-run-level-failure-in-agent-failure-prediction]]. Instrument gaps: export.arxiv.org metadata search returned HTTP 429 twice (empty body) on queries for within-problem code probes, so no negative below rests on arXiv metadata search. Ribeiro et al. text was read from the wave 4 raw extract (`research/positioning/w4/parts/fetcher-l2/raw/2512.07404v3.txt`), because the vault note [[251207404-on-llms-internal-representation-of-code-correctness]] is only about 950 words.

## What the corpus already said

The corpus holds two camps. Camp A reports large probe margins: Ribeiro et al. [[251207404-on-llms-internal-representation-of-code-correctness]] (probe beats verbal and likelihood on four 7-8B instruct models), Gros and Devanbu [[251224560-localized-calibrated-uncertainty-in-code-language-models-full-text]] (line-level probe versus verbalized, token-probability, and multisampling readouts), and Orgad et al. in general NLP. Camp B reports controls that shrink or erase the margin, almost all outside code: [[cognitive-dissonance-why-do-language-model-outputs-disagree-with-internal-repres]], [[can-llms-introspect-a-reality-check]], [[measurement-validity-and-representation-dynamics-ofconfidence-signals-in-large-l]]. On code, the width sweep had [[a-heckler-in-the-hidden-statecorrectness-signals-in-diffusion-language-models]], [[260614530-code-correctness-linearly-decodable-from-hidden-states-before-generati]], and [[which-signals-of-code-correctness-survive-distribution-shift-hidden-state-and-ca]]. The pooled-versus-within-problem cluster came mostly from agent papers ([[disentangling-task-difficulty-from-run-level-failure-in-agent-failure-prediction]], [[hard-issue-weak-model-or-bad-runrethinking-failure-prediction-for-coding-agents]]).

## What the new sources say

**Bulut, arXiv 2609.03436, Sep 2026 (new fetch)** [[its-the-problem-not-the-pathbudget-and-difficulty-confounds-in-llm-reasoning-tra]]. Supplies the identity the whole locus turns on, Eq. 1: AUROC_pooled = lambda*AUROC_within + (1-lambda)*AUROC_between, with lambda the fraction of discordant pairs from the same problem. Quote: "every question-only predictor has AUROC_within = 1/2 exactly ... in the standard design with one attempt per problem (k_c = 1), lambda = 0". Sec 4.4 reconstructs a published early-window probe on MATH with R1-Distill-Qwen-7B: pooled AUROC 0.849 [0.735, 0.919], within-problem 0.496 at t=4, while a trace-blind difficulty proxy gets 0.873 on 192K R1 generations. Math, not code; the value is the control template.

**Campos, Klassert, Ulges, arXiv 2611.07876, 5 Nov 2026 (vault)** [[which-signals-of-code-correctness-survive-distribution-shift-hidden-state-and-ca]]. The only code paper that reports pooled and within-problem AUROC side by side for probe, LAT, and output confidence, on Qwen3-Coder-30B and gpt-oss-20b (reasoning prefilled off). Definition (metrics subsection of Sec IV): within-problem AUROC is "computed over pairs of candidates from the same problem with different labels". Sec VI-C: "under language shift, within-problem AUROC lies at 0.58-0.64 for all methods and both models, against a pooled AUROC of 0.67-0.81. For Qwen3-Coder confidence performs best within problem (0.629). The trained methods reach higher within-problem AUROCs of 0.69-0.78 only for gpt-oss in distribution, but lose this advantage under shift." Table V is the decisive control: probe on the judging pass has within-problem 0.553 (pooled 0.886); on own generation at last code token 0.620 (pooled 0.895); at the last prompt token (problem only) pooled 0.891 but within 0.514. Quote: "Much of what the methods predict is thus the problem, not the candidate." Table IV (program target, Qwen3-Coder): pooled probe minus confidence is +0.029 on LCB (.844 vs .815), +0.006 on BCB (.656 vs .650), and +0.119 on the in-distribution language sets (.878 vs .759), shrinking to +0.035 under language shift (.790 vs .755). Discussion: "we recommend reporting such a within-problem measure alongside the pooled one." Limits: two models, no verbal confidence, no base/instruct, no ECE; EigenScore is a problem-level score (Sec IV-B) and cannot rank within a problem.

**Miglani et al., arXiv 2609.36783 (vault)** [[a-heckler-in-the-hidden-statecorrectness-signals-in-diffusion-language-models]]. The only code paper that centers activations within problem and folds by problem (Appendix B: "activations are centered within problem ... folds grouped by problem"). Sec 4.2, Table 1, same attempts: DiffuCoder-7B probe 0.842 vs negative token entropy 0.838 (19 mixed problems, 95 attempts); Qwen2.5-Coder (autoregressive) probe 0.677 vs completion log-probability 0.703 (56 mixed problems, 448 attempts). Quote: "Model confidence is thus a competitive baseline ... Reading hidden states provides little apparent gain." Steering results: baseline pass@1 0.433 vs 0.388 toward pass and 0.298 toward fail, so no causal use (bears on pivot criterion 4: a causal result exists, but it is a null).

**Gros and Devanbu, arXiv 2512.24560 (vault)** [[251224560-localized-calibrated-uncertainty-in-code-language-models-full-text]]. Tables 3-4 are the only code table with a partial supervision-matched control (Platt scaling on every readout), 5-fold cross-validation, execution-verified minimal-patch labels. GPT-4o: Line Verbalized AUC 0.75, scaled BSS 0.17; Probe-7B AUC 0.78, scaled BSS 0.22; Probe-0.5B AUC 0.76, scaled BSS 0.19. Qwen2.5-Coder-7B-Instruct: Line Verbalized AUC 0.71, scaled BSS 0.10; Probe-7B AUC 0.83, scaled BSS 0.33. Two consequences. (1) For GPT-4o the hidden states come from a 0.5B or 7B supervisor model reading GPT-4o's code, so the "probe" cannot be GPT-4o's own internal state; the probe margin over GPT-4o's own verbalized readout (+0.03 AUC, +0.05 BSS) is a supervised external reader's margin. (2) Platt scaling cannot change AUC, so the AUC gap survives it, but a trained verbal head or a code-text-only classifier is absent.

**Ribeiro et al., ICSE 2026, arXiv 2512.07404v3 (wave 4 raw text) and follow-up 2608.08266** [[on-the-robustness-of-llms-internal-representation-of-code-correctness]]. Sec 4.1.1: the correct candidate is "the reference solution"; the three incorrect candidates are LLM attempts from other models (BigCodeBench: Llama-3.3-70B, GPT-4o, Gemini 2.0 Flash; HumanEval: Llama-3.2-3B, Gemma-3-1B, Granite-3.3-2B). Sec 4.2.1: "the intrinsic (standard) metric on BigCodeBench hovers around 5-6% for all models" against 25% chance, and reflective variants fall to about 7% (Qwen, HumanEval, both verbal formats) or 15.3% (Mistral, True/False). Probe gains are "+13.3 to +29.0 pp" (BCB) and "+8.7 to +26.2 pp" (HE). Sec 4.1.2: LAT is fit on 10% of tasks, with each reference paired to one incorrect attempt, and validated on another 10%; verbal readouts are zero-shot. The follow-up states the confound itself (background section on contrasting pairs: "variable names or implementation style") and its mutation-only analysis tests a fit: a direction fit on bug-isolating pairs "separates them with high accuracy in isolation, yet does not transfer", with a 37.1-point accuracy drop on BigCodeBench versus 5.2 points on HumanEval. RQ2 (Sec 5) is the self-generated, within-task test (10 samples, temperature 1.0): Mistral HumanEval rank-1 41.3% vs Random 38.0%, and "Only a few comparisons reached statistical significance."

**Pre-generation difficulty probes, arXiv 2602.09924 (vault)** [[llms-encode-their-failures-predicting-success-from-pre-generation-activations]]. Table 2, LiveCodeBench, target Pass@5, columns Linear / MLP / TF-IDF / Length: Qwen2.5-Coder-3B 0.91 / 0.56 / 0.86 / 0.64; Qwen2.5-Coder-7B 0.90 / 0.89 / 0.84 / 0.61; R1-Distill-Qwen-7B 0.81 / 0.80 / 0.83 / 0.59; GPT-OSS-20B (low) 0.71 / 0.65 / 0.66 / 0.64. Code is the one place where a prompt-text TF-IDF baseline is reported next to a pre-generation probe: it recovers 0.84-0.86 of the 0.90-0.91 probe AUROC for Qwen2.5-Coder and beats the probe for R1-Distill. LiveCodeBench release-date splits are used for contamination control (dataset-construction paragraph). Column labels were read from the table header; the targets (Pass@5, task success 0.14-0.30) differ from Di Cicco's first-attempt pass/fail, so numbers are indicative, not additive.

**Di Cicco, arXiv 2606.14530 v3 (vault)** [[260614530-code-correctness-linearly-decodable-from-hidden-states-before-generati]]. Sec 3: 444 LiveCodeBench tasks, Qwen3-4B-Instruct-2507, one attempt per task ("The single sample per task ensures no task appears in both train and test"), probe AUC 0.881 +/- 0.008, 0.842 +/- 0.010 after residualizing against prompt length, prompt-length baseline 0.657 (Table 3). By Bulut's Eq. 1 this design has lambda = 0, so every pair is cross-problem. The only confound control is prompt token count (Tables 3-4), not a prompt-text or difficulty baseline.

**Liu et al., arXiv 2312.03729 (vault)** [[cognitive-dissonance-why-do-language-model-outputs-disagree-with-internal-repres]]. Sec 3: "the superior calibration and accuracy of probes over queries might not seem surprising given that probes are trained many-shot while queries use the model zero-shot." Fine-tuned GPT2-XL queried directly: probes were "1.7% better accuracy than fine-tuned model queries on BoolQ", but queries were "6.9% and 4.0% better" on SciQ and CREAK. Sec 5, Eq. 1 ensemble improves on the probe in 4 of 6 cases. General NLP, GPT2-XL and GPT-J only. This is the only fetched supervision-matched probe-versus-query comparison.

**Disentangling (arXiv 2610.05572)** [[disentangling-task-difficulty-from-run-level-failure-in-agent-failure-prediction]] and **hard-issue (arXiv 2611.08285)** [[hard-issue-weak-model-or-bad-runrethinking-failure-prediction-for-coding-agents]]. Agent, not function-level: ">99.93% of the underlying positive-negative pairs compare different model-task units", difficulty oracle pooled AUROC up to 0.945 and 0.500 within task; hidden-state probes on C4 reach mean within-task AUROC 0.509 (C4-Q) and 0.513 (C4-L) although hidden states encode trajectory length (R^2 up to 0.98). Hard-issue: reference score 0.92 AUROC vs about 0.62 for trajectory predictors; gain beyond difficulty and ability "statistically equivalent to zero".

**Out-of-code controls.** [[measurement-validity-and-representation-dynamics-ofconfidence-signals-in-large-l]] (Ghosh, Kumar, Garg, 2610.25846; Sec 4.1, Table 1): the claim "TF-IDF matches probes in 9 of 11 cells" is narrower than the locus text implies. It concerns the onset-layer probe on retrieval cells, with a median-split semantic-entropy label (not correctness), five Qwen2.5 models, no code; the follow-up reports 12 of 24 cells overall. It is an onset-depth result, not a peak-versus-baseline result. [[hidden-error-awareness-in-chain-of-thought-reasoningthe-signal-is-diagnostic-not]] (MATH-500): probe 0.953 vs verbalized 1-5 0.67, self-consistency 0.823, but a TF-IDF text-surface classifier on the first reasoning step reaches only 0.59 vs probe 0.79 (stated in the paper's introduction and Table 2 discussion), and four causal interventions fail. [[can-llms-introspect-a-reality-check]] (2605.26242): layer-0 input-only probes "match or exceed" models' in-context predictions of probe-derived labels; it concerns introspection, not confidence, so only its control design transfers.

## Evidence synthesis

Three different confounds are being run together under "the probe advantage is an artifact", and the fetched code papers control different ones, never all.

(1) Difficulty (between-problem). Eq. 1 of Bulut makes the diagnostic exact. For function-level code the share of same-problem pairs is tiny even with repeats: my arithmetic, for 164 problems with 10 samples each and balanced 5 pass / 5 fail per problem, is 164*25 / (820*820) = 0.6% same-problem pairs, so a pooled AUROC is about 99% a between-problem number, close to the agent papers' 99.93%. Empirically on code: Campos et al. Table V (prompt-only probe pooled 0.891, within 0.514), Campos et al. Sec VI-C (all methods 0.58-0.64 within), and the 2602.09924 TF-IDF row (0.84-0.86 vs probe 0.90-0.91). Di Cicco's 0.842 therefore says nothing about within-problem signal; its length residualization removes a weak difficulty proxy (0.657), not a strong one.

(2) Supervision asymmetry. Probe fit on labels versus zero-shot readout. Liu et al. show this flips the winner in general NLP; the only code table with a partial control is Gros and Devanbu, where Platt-scaled verbal keeps a 0.03 (GPT-4o, external 0.5B/7B reader) to 0.12 (Qwen) AUC deficit. No code paper trains a verbal head, a logit-feature classifier, or a code-text-only classifier on the same execution labels (searched vault claims digest for supervised, text-only, input-only, text-surface; hits only Liu, Hidden-error-awareness on MATH, and 2602.09924). This is the open residual.

(3) Provenance/style (within-problem but not within-model). Ribeiro's headline is the only code result that is within-task by construction, so difficulty cannot explain it. But Sec 4.1.1 pairs a human reference with other models' failing attempts. The intrinsic readout choosing the reference only 5-6% of the time on BCB (chance 25%) shows the label is strongly anti-correlated with model likelihood: a supervised reader that learns the sign would trivially beat it (inference, untested; the reversed ranking's accuracy is not reported). A mean-difference direction fit on reference-versus-LLM pairs can use "human-like vs LLM-like" as a shortcut; the follow-up's mutation-only direction fails to transfer on BCB (37.1-point drop), which fits that reading but does not prove it (HumanEval shows only 5.2 points). Ribeiro RQ2 is the cleaner test (self-generated, within-task) and its gains are small and mostly non-significant.

Where evidence is best aligned: three independent within-problem comparisons of probe against the model's own output confidence on self-generated code find a tie or a probe loss (Miglani et al. DiffuCoder 0.842 vs 0.838 and Qwen2.5-Coder 0.677 vs 0.703; Campos et al. Qwen3-Coder within 0.620 vs confidence 0.629), with one exception where the probe leads (gpt-oss in distribution, 0.69-0.78, vanishing under shift). None includes a numeric or categorical verbalized confidence or a per-candidate sampling-agreement score. So the specific L2 claim, probe versus verbal on code within problem under matched supervision, has no direct test; the indirect evidence leans to a small margin.

### Position A: the probe advantage on code is real unexpressed information
Best case. Ribeiro is within-task, so difficulty is controlled; the margin is +8.7 to +29.0 pp across four models and two benchmarks, and verbal readouts sit at or below chance (Sec 4.2.1). Gros and Devanbu Table 4 gives a calibrated, cross-validated margin (Qwen: AUC 0.83 vs 0.71 verbal, BSS 0.33 vs 0.10 after Platt). Miglani et al. show the code probe survives small semantic mutations (AUC 0.670 on 392 MBPP+ mutants, 0.692 on 334 HumanEval+ mutants), which argues against pure style. Di Cicco's signal survives length control. In math, the first-step probe beats a text classifier by 0.20 AUROC (0.79 vs 0.59). On diffusion code models the hidden-state probe beats supervised LR-on-entropy by 0.08 to 0.10 AUC on MBPP (probing-functional-correctness-in-diffusion-language-models-full-text, Tables 10-12, e.g., Dream 0.879 vs 0.776), a supervision-matched readout comparison on code, albeit on non-autoregressive models and pooled.

### Position B: the advantage is mostly difficulty, supervision, and provenance
Best case. Pooled AUROC is about 99% between-problem (Eq. 1; Disentangling 99.93%), prompt-only probes carry the same pooled score as candidate-aware probes (Campos Table V), TF-IDF on LiveCodeBench prompts recovers 0.84-0.86 of 0.90-0.91 (2602.09924 Table 2), within-problem AUROC for every method is 0.58-0.64 (Campos Sec VI-C), and the only autoregressive code probe-versus-logprob within-problem comparison has the probe losing (0.677 vs 0.703). Ribeiro's design pits fitted probes against zero-shot readouts and a human-reference class against other-model class. In general NLP, supervision-matching erases the probe advantage in 2 of 3 datasets (Liu et al. Sec 3). The steering null (Miglani et al., 0.433 vs 0.388/0.298) says the direction is not causally used.

### Reconciliation
The sides are mostly answering different questions. A is right that a within-task, execution-labeled, fitted probe discriminates correct from incorrect candidates better than zero-shot readouts do (a descriptive fact about a supervised reader). B is right that this does not establish "unexpressed internal knowledge" because the reader is supervised and the contrast classes differ in provenance, and that the pooled numbers in the other probe papers are difficulty. What neither side has is the 2x2 that matters: {probe, supervised own-readout, verbal, input-only} x {pooled, within-problem}, on the same self-generated function-level samples. The locus's two cited side-B facts need correcting: Di Cicco's 0.842 vs 0.657 is not within-problem evidence (k=1, lambda=0), and "TF-IDF matches probes in 9 of 11 cells" is an onset-layer, semantic-entropy-label, non-code result.

## Committed position

The "probe beats the model's own readout" headline on code is occupied only in its uncontrolled form, and the controlled form is probably much smaller than the occupant's +9 to +29 pp. Three independent confounds each have a documented mechanism in a fetched full text: pooled AUROC is about 99% between-problem at function-level scale (Bulut Eq. 1, my 0.6% same-problem-pair arithmetic, Campos Table V); fitted probes are compared with zero-shot readouts (Ribeiro Sec 4.1.2; Liu et al. Sec 3 shows the winner flips on 2 of 3 datasets when supervision is matched); and Ribeiro's contrast is human reference versus other-model failures, with the likelihood readout at 5-6% accuracy against 25% chance on BigCodeBench. The within-problem probe-versus-own-confidence comparisons on code that do exist (Miglani 0.677 vs 0.703; Campos 0.620 vs 0.629) show ties, which I read as the best current estimate: a probe's within-problem edge over a well-formed own-confidence readout on self-generated code is within about 0.05 AUROC and may be zero. I would not build a paper's spine on "the disconnect exists"; I would build it on the controlled test, which is publishable under TMLR's accuracy-and-clarity criterion whichever way it comes out, and which no fetched work runs.

- **Position:** On code, "probe over own readout" is OCCUPIED as an uncontrolled claim (Ribeiro) but the controlled claim, a probe versus supervision-matched own readouts versus input-only baselines, scored within problem on self-generated samples with execution labels, is NARROW and unrun; the evidence predicts a small or null controlled gap.
- **Confidence:** medium (about 65%) on "controlled gap is at most about 0.05 within-problem AUROC"; high (about 85%) that the controlled test is unrun in fetched work; medium-low that the supervised-matched verbal head also fails to close it (untested on code).
- **Provisional verdicts for the R1 components this locus decides:**
  - L2 Q1, probe vs stated confidence, token probability, sampling agreement on code with execution labels, uncontrolled: **OCCUPIED** (Ribeiro Sec 4.2.1 for whole-solution probe vs verbal; Campos Table II/IV for probe vs confidence vs EigenScore; sampling agreement only at problem level).
  - L2 Q1 with controls (supervision-matched readout plus input-only baselines plus within-problem scoring, same samples): **NARROW**. Residual in one sentence: the same-sample comparison of probe, trained own-readout (logit-feature or verbal head fit on the same execution labels), prompt-only and candidate-text-only baselines, and verbal numeric and categorical confidence, scored pooled and within problem on self-generated function-level code. Closest work on each side: Ribeiro et al. 2512.07404 (probe vs zero-shot verbal, within-task, provenance-confounded) and Campos et al. 2611.07876 (pooled vs within, no verbal, no trained own-readout); general-NLP anchor Liu et al. 2312.03729. A21 test: residual is a label protocol/control (not a model swap) with code-specific reasons (execution labels allow identical supervision for all readouts; function-level difficulty is recoverable from prompt text, TF-IDF 0.84-0.86 on LCB; reference-versus-LLM provenance). Passes.
  - L2 Q13 (A16), pooled vs within-problem discrimination for code confidence: **NARROW** (not CLEAN). Occupant: Campos et al. 2611.07876 (concurrent, 5 Nov 2026) reports both for probe, LAT, and output confidence on two models. Residual: verbal stated confidence and per-candidate sampling agreement (EigenScore is problem-level and has within-problem AUROC 0.5 by construction), base/instruct pairs, reasoning on, and at least 100 mixed problems. Closest: Campos et al. (code, no verbal) and Disentangling 2610.05572 (agents, general decomposition).
  - L1 Q6 (recalibration as a control separating mapping from information): **NARROW**. Gros and Devanbu Tables 3-4 apply Platt to every readout, but only at line level and for edited-line labels; no function-level correctness study separates calibration from discrimination with a trained control.
  - Pivot A14 (trained stated confidence closes the discrimination gap): **not triggered by anything fetched**, but not excluded either; the locus found no code study that trains verbal confidence on execution labels. Pivot A15 (causal intervention already shows where information is lost on code): **not triggered**; Miglani et al.'s steering null on DiffuCoder is the only code intervention and it localizes nothing.
  - Pivot A21 for L2 as spine: **survives**, but only if the paper adopts the controlled test as its headline; a "we show probes beat verbal on code" headline is OCCUPIED and fails A21.
- **Boundary conditions:** applies to function-level, single-turn code correctness with unit-test labels on 3-30B open models, and to the readouts and models in the fetched code papers (Qwen2.5/3 Coder, Mistral, CodeLlama, OpenCoder, gpt-oss, DiffuCoder). It does not cover agents (the agent papers support the difficulty point but at 99.93% cross-unit by their corpora), reasoning-on probing (Campos prefill disables reasoning), or sub-solution granularity (Gros and Devanbu show a larger probe margin at line level, 0.71 to 0.83 AUC on Qwen, which this locus did not shrink).
- **What would change this position:** (a) a code study training a verbal or logit-feature head on the same execution labels and showing it still trails the probe by at least 0.08 within-problem AUROC on at least 100 mixed problems; (b) Ribeiro-style results replicated with all candidates self-generated by the scoring model (removing the human-reference class) and with a text-only supervised baseline; (c) a within-problem Qwen2.5/3-Coder probe margin over output confidence above 0.05 with a CI excluding zero; (d) evidence that the 0.677 vs 0.703 tie is an artifact of Miglani's 56-problem sample (the CI is not reported). Conversely, a sign-reversed log-probability baseline on Ribeiro's data reaching probe-level accuracy would confirm the provenance reading.
- **Evidence weight:** For the artifact reading: 3 code full-texts with direct numeric support (Campos Tables IV-V and Sec VI-C; 2602.09924 Table 2; Miglani Table 1), 1 design analysis of the occupant (Ribeiro Sec 4.1.1 plus the follow-up's own caveat), 1 general-NLP supervision-matching result (Liu), 2 agent papers and 1 math paper on the difficulty identity (Disentangling, Hard-issue, Bulut). For the real-signal reading: 1 within-task code occupant with large margins but confounded design (Ribeiro), 1 line-level calibrated result with partial control (Gros and Devanbu), 1 diffusion-model result with a supervised-entropy control on MBPP, 1 math result with a text-surface control (Hidden-error-awareness). Samples are small where within-problem (19 and 56 mixed problems), and the strongest claims in both camps come from preprints within the six-month concurrency window (A23: 2611.07876, 2609.36783, 2609.03436, 2610.05572, 2611.08285, 2606.14530 are concurrent; 2602.09924 and 2512.24560 are preprint only; 2512.07404 is published, ICSE 2026).

## Open questions

- Does a sign-reversed or fitted log-probability and length classifier reach LAT-level accuracy on Ribeiro's QA_BCB and QA_HE? The data are public (github.com/sanadlab/code-repe, named in the paper); not fetched.
- The 2602.09924 Table 2 column mapping (Linear/MLP/TF-IDF/Length) was read from the header; verify against the PDF before quoting.
- Campos Table II layout was garbled in extraction (summary already says so); the within-problem numbers I cite come from Sec VI-C, Table V, and Table IV text, which parsed cleanly.
- Miglani et al.'s CIs for 0.677 vs 0.703 (56 mixed problems) are not in the sections I read; paired CI not verified.
- Vu et al. and Bui et al. [[250112934-correctness-assessment-of-code-generated-by-large-language-models-usin]] baselines (do they include text-only classifiers?) were not re-read; Ribeiro's close citers cite both.
- No code study of a trained verbal head (SFT or RL on execution labels): searched vault digest only; arXiv metadata search failed (HTTP 429), so this negative is an instrument gap, not a zero.
- Per-candidate sampling-agreement (cluster size, MBR) within-problem AUROC against probe on code: not found; EigenScore in Campos is problem-level.
- Recommend a follow-up locus: "trained stated confidence on code (A14)", since it decides pivot criterion 3 and shares the supervision-matching control.
