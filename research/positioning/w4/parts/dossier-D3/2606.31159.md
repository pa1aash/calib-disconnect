# Security Calibration in LLMs for Code (2606.31159)
Status: concurrent (arXiv v1 30 Jun 2026, preprint only). Source: research/notes/an-empirical-study-of-security-calibration-in-large-language-models-for-code.md (11.9k words). Text basis: FULL TEXT.
Measured: calibration of confidence for functional correctness and for security of generated code, with False Trust (confidence >= 0.8 yet insecure), six temperatures, calibration-guided repair and gating (Sections IV-A to V).
Models and benchmarks: GPT-4o-mini, Gemini-2.0-Flash, Qwen3-Coder-Next (80B) (Section IV-A2); SALLM (100 tasks, 20 samples per task and temperature) and AICGSecEval (125 repository prompts, four languages) (Sections IV-A1, IV-B1).
Findings: verbalized security ECE 0.456 to 0.481 (GPT-4o-mini), 0.408 to 0.421 (Qwen), 0.247 to 0.263 (Gemini) (Section V-A); functional calibration worse than security calibration (abstract); calibration-guided repair gives limited gains with functional regressions.
Leaves open: no probes; no base or reasoning contrast; whole-sample labels from vulnerability tests, not a release-date split; the repair test is security-driven, not per-requirement.
