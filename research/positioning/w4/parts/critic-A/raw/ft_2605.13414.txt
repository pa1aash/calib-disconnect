                                                                                        Abstract
                                                    Deploying language models as autonomous agents requires more than per-task
                                                    accuracy: when an agent faces a queue of problems under a finite token budget, it
                                                    must decide which to attempt, in what order, and how much compute to commit
                                                    to each, all before any execution feedback is available. This is the prospective
                                                    form of metacognitive control studied for decades in human cognition, yet whether
                                                    language models possess it remains largely untested. We introduce TRIAGE, an
                                                    evaluation framework in which a model receives a task pool and a token budget
                                                    calibrated to its own baseline cost, and commits to a single ordered plan that
                                                    jointly encodes selection, sequencing, and per-problem allocation. Plans are scored
                                                    against an oracle built from the model’s measured solvability and token costs, using
                                                    triage efficiency normalized between random and oracle performance, together
                                                    with normalized regret relative to the oracle. We evaluate frontier and open-source
                                                    models, with and without reasoning enabled, across competition mathematics,
                                                    graduate-level science, code generation, and expert multidisciplinary knowledge,
                                                    and find that current language models exhibit substantial gaps in prospective
                                                    metacognitive control, revealing a previously unmeasured capability dimension
                                                    with direct implications for resource-efficient agent deployment.


                                        1    Introduction
                                        Scaling test-time compute has become a major paradigm for improving LLM reasoning [33], but it
                                        has also made compute allocation a central unsolved problem: current reasoning models lack reliable
                                        prospective control over their own compute expenditure, and adaptive allocation per problem can yield
                                        substantial efficiency gains [33, 3]. Reasoning models can expend excessive tokens even on trivial
                                        problems [5] and underthink hard ones, prematurely abandoning promising reasoning paths [39].
                                        Unconstrained agents, similarly, can consume thousands of tokens on agentic tasks and still fail,
                                        exhibiting analysis paralysis and wasted compute that correlates with decreased performance [7].
                                           This creates a concrete deployment problem: agents built on these models face real resource con-
                                        straints, including token budgets, tool-call limits, and latency windows, and must decide which tasks
                                        to attempt before committing resources. TRIAGE isolates the setting in which selection, ordering,
                                        and allocations are committed before execution feedback; interactive replanning is complementary.
                                        A resource-rational agent should allocate finite compute to the tasks where its expected return is
                                        highest [24]. In practice, this means an LLM facing a queue of problems under a token budget should
                                        abstain from attempting ones it cannot solve, spend less on easy ones, and safely commit sufficient
                                        resources to each attempted problem so that under-allocation does not expend budget on partial or
                                        incomplete solutions that yield no return. This is the same strategy a student applies on a timed exam,
                                        and an instance of the capability that Nelson and Narens [30] formalized as metacognitive control:
                                        regulating effort allocation based on judgments of one’s own knowledge state.
                                          Recent work suggests LLMs have some of this capability in isolation: large language models
                                        can predict whether they will answer a question correctly [15], yet reasoning-trained models can

be worse at abstaining on unanswerable questions [18]. Barkan et al. [4] evaluated prospective
confidence and sequential task-acceptance decisions, finding systematic overconfidence that does
not consistently diminish with scale or reasoning augmentation. The critical capability for an LLM
planner is not just predicting token cost or knowing when to abstain from a single question, but
managing a portfolio: given a set of tasks and a shared budget, selecting which to attempt, estimating
cost, and ordering execution to maximize value. This is the problem that many real-world agentic
deployments face: coding agents working through backlogs of issues, research agents decomposing
queries into sub-questions of varying difficulty, and planning agents budgeting compute across
subtasks of a larger goal all require cross-task prioritization under finite compute. Existing per-task
budgeting methods estimate reasoning budgets for individual problems [12, 23], and external batch
schedulers order requests for throughput [14, 9]. However, whether LLMs can themselves perform
the joint optimization of assessing their own feasibility, cost, and priority across a heterogeneous task
set under a shared budget, before any execution feedback, remains largely untested.
   We introduce TRIAGE, an evaluation framework for prospective metacognitive control under
resource constraints. The construct has three components. Metacognitive control is the use of
self-knowledge to regulate behavior, graded by the consequences of the model’s plan rather than
by verbalized confidence [1]. Prospective denotes that all decisions are committed before any task
is attempted, distinguishing committed resource-allocation decisions from retrospective measures
of confidence or post-hoc calibration. Prospective confidence judgments are also studied in prior
work [15, 19]; TRIAGE requires a joint resource-allocation plan. Resource constraints refers to a
finite shared budget, output tokens by default, that the model’s behavior consumes [12]. In TRIAGE,
a model receives a set of problems, point values per problem, and a token budget calibrated to its own
baseline cost on the set. It returns a single ordered plan specifying which problems to attempt, how
many tokens to allocate to each, and in what order. We evaluate these plans using fixed, model-specific
baseline outcomes and token costs under advisory and allocation-enforced scoring rules. This design
operationalizes three foundational control functions from Nelson and Narens [30] in their prospective
form: selection (which problems to attempt), allocation (how much compute to commit per problem),
and termination (where to commit budget cutoffs ex ante). TRIAGE evaluates the control output
directly rather than asking the model to verbalize its underlying judgments, following work that tests
LLM metacognition behaviorally rather than relying on self-reports [1]. Just as human learners plan
effort allocation under time pressure [34], an autonomous agent must jointly optimize these decisions
to maximize expected utility under finite inference limits.
   We evaluate 20 models in 30 configurations, including 10 models evaluated both with and without
extended reasoning, across four domains: competition mathematics (AIME 2024–2025), graduate-
level science (GPQA Diamond; 32), code generation (LiveCodeBench; 13), and multidisciplinary
expert knowledge (Humanity’s Last Exam; 31).
We find that current language models exhibit substantial and uneven gaps in prospective metacognitive
control. Triage performance varies across domains, and extended reasoning has configuration-
dependent effects on triage quality. Across repeated planning runs, performance falls substantially
when per-problem allocations are enforced rather than treated as advisory. Allocation counterfactuals
further diagnose budgeting errors, which persist in control pools containing only problems the
model previously solved. The expanded GPQA-Abstain probe reveals substantial variation in
unanswerability recognition, with paired standard-versus-extended comparisons favoring extended
reasoning on average. Together, these experiments characterize a previously unmeasured capability
dimension with direct implications for resource-efficient agent deployment.


2     Related Work

2.1   Metacognition in Large Language Models

Metacognition, the capacity to monitor and regulate one’s own cognitive processes [30], has become a
central concern in LLM evaluation. Research examines three aspects of metacognition: metacognitive
knowledge (can the model identify what a task requires?), metacognitive monitoring (can the model
judge whether it will succeed?), and metacognitive control (can the model act on those judgments to
regulate its behavior?). What remains largely untested is prospective control over a task portfolio:
jointly selecting, ordering, and allocating compute under a shared budget before execution feedback.


                                                   2
Metacognitive knowledge and monitoring. Kadavath et al. [15] provided the foundational result
on monitoring, showing that LLMs can predict which questions they will answer correctly, with
calibration improving at scale. Didolkar et al. [8] demonstrated that LLMs also possess metacognitive
knowledge: given a math problem, frontier models can assign meaningful skill labels and use skill-
matched exemplars to improve reasoning, establishing that models can assess task properties. Xiong
et al. [40] systematically benchmarked confidence elicitation methods and found that LLMs tend to
be overconfident when verbalizing confidence, though both calibration and failure prediction improve
with scale. Wang et al. [38] formalized the separation of metacognitive ability from raw cognitive
ability via their DMC framework, finding that stronger LLMs exhibit stronger metacognition and
that higher measured metacognitive ability is associated with better abstention performance. At the
mechanistic level, Li et al. [22] demonstrated that LLMs can monitor and control a low-dimensional
subspace of their internal activations via a neurofeedback paradigm, providing direct evidence of
metacognitive access to internal states, though limited to concurrent activations rather than prospective
task-level judgments.
These results are counterbalanced by evidence of systematic failure. Kapoor et al. [16] showed that
verbalized confidence is poorly calibrated for open-ended generation and that supervised fine-tuning
through model features substantially improves uncertainty estimation. Griot et al. [10] found that
LLMs provide confident answers to medical questions even when correct options are entirely absent,
revealing a disconnect between stated confidence and actual capability.
Ackerman [1] used behavioral paradigms where the model must decide before answering whether to
attempt or defer (the Delegate Game) and found limited, context-dependent metacognition. Steyvers
and Peters [35] organize these mixed findings by distinguishing metacognitive sensitivity (ranking
own performance across items) from calibration (matching confidence to success rate), noting that
the two can vary independently and that neither is reliably strong across models and domains.

From monitoring to control. TRIAGE evaluates how task selection, ordering, and token allocation
interact under a shared budget. The closest prior work to ours is Barkan et al. [4], who explicitly
distinguish in-advance from after-the-fact confidence and test prospective self-assessment on coding
and agentic tasks (SWE-Bench Verified). They find systematic overconfidence, without consistent
gains in prediction accuracy from scale or reasoning augmentation. Their resource-acquisition
experiment tests sequential contract acceptance with success rewards, failure penalties, and feedback
from prior outcomes. It does not require jointly selecting, ordering, and assigning token allocations
across a visible task pool under one shared budget before feedback.
AbstentionBench [18] evaluates abstention across 20 datasets and reports an average ∼24% reduction
in abstention in its reasoning-fine-tuning comparisons. We use its GPQA-Abstain and MMLU-
Math-Abstain variants in our unanswerable-item injection experiments. AbstentionBench evaluates
abstention on individual questions; TRIAGE evaluates a joint commitment to task selection, ordering,
and token allocation across a task pool under a shared budget.
Across this literature, a consistent picture emerges: LLMs possess metacognitive knowledge and
some monitoring ability, but both are contested in degree and fragile across domains. TRIAGE
evaluates the quality of a joint plan specifying task selection, execution order, and token allocations
under a shared budget, committed before execution feedback. Per-task self-assessment alone is
insufficient: the model must also compare feasibility and cost across tasks while respecting the
shared constraint. Whether current models can make this transition from single-task monitoring to
portfolio-level resource allocation is what TRIAGE is designed to test.

2.2   Compute Allocation for LLM Reasoning

The test-time compute scaling paradigm [33] has made compute allocation a practical problem.
Reasoning models overthink trivial problems [5], underthink hard ones [39], and in agentic settings
exhibit analysis paralysis that correlates with decreased performance [7]. Existing methods address
this waste, but split on who allocates and at what granularity, and neither side covers the full problem.
On the self-assessed side, TALE [12] has the LLM estimate a token budget before solving a problem,
and SelfBudgeter [23] trains the model to emit a budget before its chain of thought. Both are prospec-
tive and self-assessed, but per-task: the model decides how long to spend, never whether to attempt
at all, and there is no shared budget linking decisions across tasks. On the systems side, external


                                                   3
predictors schedule LLM inference for serving efficiency through length-bucket classification [14],
listwise ranking [9], or interval prediction under uncertainty [6]. These operate at the portfolio level,
but the predictor is external to the LLM, the objectives concern latency and throughput, and the
model’s own judgment of what it can solve plays no role.
Existing benchmarks test related but distinct capabilities. PlanBench [37] evaluates plan generation,
verification, and reasoning about execution in classical planning domains, with external validation;
it does not evaluate a model’s selection and token allocation across problems based on its own
measured solvability and costs. τ -bench [43] evaluates tool-using agents in user interactions through
policy-constrained tasks and final database-state checks, and GAIA [28] provides a heterogeneous,
difficulty-leveled agent benchmark with validated ground truth. TRIAGE instead evaluates an LLM’s
joint selection, ordering, and token allocation across a task pool under a shared budget, with the plan
committed before execution feedback.
A gap remains in evaluating joint resource allocation under a shared budget. Single-task confidence
benchmarks isolate monitoring; external schedulers isolate allocation; neither evaluates a model’s
joint selection, ordering, and token allocation under a shared budget. TRIAGE is designed to close
this gap as an evaluation. The model produces a plan (selecting tasks, estimating costs, and ordering
execution), which we score by simulating its consequences against fixed, model-specific baseline
outcomes and token costs, using triage efficiency and normalized regret to assess the plan under a
shared budget. Accurate per-task self-assessment alone is insufficient: the model must also compare
feasibility and cost across tasks while respecting a shared constraint.

3     TRIAGE Evaluation Framework
3.1   Prospective Metacognitive Control

Effective problem-solving under constraint requires more than the capacity to execute individual
tasks; it requires metacognitive control over how that capacity is deployed, and for an agent operating
under a finite execution budget, that control is exercised as prospective planning: a commitment,
made before any problem is attempted, to which problems will be pursued, in what order, and how
much of the budget each will receive. Cognitive psychology distinguishes an object level, where a
task is executed, from a meta level, which monitors the object level and exerts control over it [30, 20].
Two control functions of the meta level, what to attempt and how long to persist on what is attempted,
are the levers behind human study-time allocation [34, 27] and the metacognitive regulation of study
effort before testing [2]. We benchmark functional analogues in language models.
Relative to task execution, TRIAGE distinguishes prospective decisions committed before execution
from concurrent decisions made during execution and retrospective judgments made afterwards.
We focus on the prospective setting, analogous to pre-study Ease-of-Learning judgments in the
laboratory [30, 21] and initial test plans in applied settings, for three independent reasons.

Methodological isolation. Once feedback is allowed during execution, observed performance can
       reflect both prospective judgment quality and adaptive replanning. Evaluating a committed
       plan without intervening feedback isolates the up-front decision from later revisions. Human
       studies likewise use controlled study-time conditions to distinguish metacognitive regulation
       from learning performance [2].
Deployment realism. LLM-driven systems already make task-level resource commitments before
       execution outcomes are known. Deep research agents can decompose queries into parallel
       sub-agents with separate context windows and query-dependent effort guidelines, with the
       lead agent waiting for a batch to finish before proceeding [11]. Deep research agents also
       issue batches of tool calls before receiving their results; W&D studies how the number and
       scheduling of parallel calls affect performance and efficiency [25]. Coding agents such
       as SWE-agent operate on repository issues under preassigned per-instance inference-cost
       budgets, automatically submitting existing edits when the budget is exceeded [42]. Under a
       shared deployment budget, resources spent on unsuccessful attempts reduce what remains
       for other work. TRIAGE isolates the corresponding LLM planning decisions across a task
       pool: what to attempt, in what order, and with what token allocations.
Construct priority. Replanning revises earlier prospective decisions in light of execution feedback.
       To measure what mid-execution adjustments add, we first need a clean measurement of the


                                                   4
         up-front plan in isolation, and that requires evaluating planning without any feedback during
         execution.

Tokens as the control variable. Classical study-allocation work uses time as the meta-level control
variable. In autoregressive language models, output tokens are the natural unit of expended effort:
generation time, compute, and monetary cost are all approximately proportional to token count, and
the central paradigm of test-time compute scaling treats per-problem token allocation as the system’s
primary lever for adapting to problem difficulty [33, 12]. Tokens are therefore the operational analog
of time in study-allocation theory, with the additional property of being exactly measurable.

Distributional self-knowledge and binding plans. Agent pipelines can decouple planning from
execution into separate inference calls [41]. In TRIAGE, the planner does not introspect on an
ongoing computation; it predicts the behavior of a solver using the same model checkpoint under
standard execution conditions. We treat this as the deployment-relevant form of self-modeling. The
plan is operationally binding in regime E: declared allocations are enforced by the scoring rule against
the fixed reference completion, converting the forecast into a resource commitment. We study this
enforced setting alongside the unconstrained one as a secondary regime (§3.2).

Four primitives. Prospective metacognitive control under a finite execution budget reduces to
four jointly exercised judgments: (i) feasibility, whether the model can solve the problem? (ii) cost,
how many tokens will it take? (iii) selection, which subset to attempt? and (iv) sequencing, in what
order, given that budget exhaustion truncates the tail? Existing LLM benchmarks isolate slices of
this set: per-item confidence calibration covers (i) [4]; abstention covers a hard form of (i) without a
budget [18]; per-task budget control covers (ii) for a single item [23]. TRIAGE measures the joint
exercise of all four primitives under a finite budget.

3.2   Problem Formulation

We formalize TRIAGE for a single task pool, a finite set of problems sharing a domain and a budget,
the unit of work the agent commits to in a single planning step before any execution feedback arrives.

Setup. A task pool P = {p1 , . . . , pn } contains finitely many problems. For each problem pi and
a fixed solver configuration M : vi ∈ R>0 is the point value, observable to M ; yi ∈ {0, 1} records
whether M solved pi in its Phase-0 reference completion, unobservable to M at planning time;
and ci ∈ Z>0 is the recorded output-token cost of that completion, also unobservable at planning
time. These reference measurements remain fixed during scoring. The solver configuration specifies
the model checkpoint, reasoning mode, sampling settings, and generation limits (Appendix B.1).
Repeated-run analyses are described in Appendix C.4.

Budget. The budget is B(M, α) = ⌊α · ni=1 ci ⌋ with α ∈ (0, 1]; the floor reflects that token counts

references coincide; normalized regret supports substantive full-budget comparisons. The budget
applies to simulated task-solving output costs; input tokens and tokens used to generate the plan are

Action. The model produces an ordered plan π = (i1 , . . . , ik ) with 0 ≤ k ≤ n, indexing a selected

token allocations.

Execution. Plans are scored in plan order against the fixed reference outcomes and costs under two
regimes, which differ in whether the per-problem allocations ai are binding.
Unconstrained regime (U). Each reached problem incurs its measured reference cost ci ; only the
global budget B binds. Scoring proceeds through π until reaching an item whose measured cost
exceeds the remaining budget, at which point scoring stops. Problem ij contributes vij yij to the
achieved value if reached, and zero otherwise. Per-problem allocations are advisory.

Constrained regime (E). Each positive-allocation problem ij is scored against its fixed reference
completion: it contributes vij yij if aij ≥ cij , and zero otherwise. The full allocation aij is deducted
from the remaining budget regardless of outcome. Scoring proceeds through π until reaching an item
whose allocation exceeds the remaining budget, at which point scoring stops.
The two regimes probe complementary aspects of prospective control [30]. In regime U, feasibility
and cost judgments matter through selection and sequencing, while per-problem allocations are
advisory. In regime E, allocations additionally bind under the scoring rule, making the planner’s
resource commitments consequential. We write VM (π) for achieved value under the specified regime
and report results in both.

Measuring triage skill. We use normalized measures to evaluate how well the planner’s com-
mitted plan π acts on its predictions of (yi , ci ) under budget B . A raw value comparison VM (π) is
uninformative on its own: its magnitude depends on pool difficulty and on B , which vary across
cells. Following the reference-based logic of forecast skill scores [29], we normalize achieved value
between an uninformed random reference and a fully informed oracle. We also report normalized
regret relative to the oracle.

4   Experimental Setup

Models. We evaluate 20 models yielding 30 model–mode configurations across frontier and open-
source families (Qwen 2.5/3/3.5, GPT-OSS, Claude, DeepSeek, Gemini, GLM, GPT-5, Kimi). Ten
models are evaluated in both standard inference and extended-reasoning configurations. Full model
identifiers, providers, size labels, reasoning configurations, and serving settings are provided in
Appendix B.

Datasets and task pools. We construct task pools from four domains: competition mathemat-
ics (AIME 2024–2025), graduate-level science (GPQA Diamond [32]), code generation (Live-
CodeBench [13]), and multidisciplinary expert knowledge (Humanity’s Last Exam [31]). Live-
CodeBench uses 2025-dated problems from the evaluated release_v6 snapshot. We retain text-only
HLE items outside mathematics, biology/medicine, and chemistry/materials. Each dataset is par-
titioned into task pools of nominal size nchunk = 30 to limit planner context length, motivated by
prior evidence of long-context degradation [26]. The partitioning procedure is specified in Additional
Experiments. Each pool has its own budget, oracle, and random reference. Scores are averaged
equally over available scored pools within each model configuration, dataset, budget condition, and
planning run; HLE combines pools across its retained categories.
To probe sensitivity to unanswerable items, we mix answerable items with annotated unanswerable
items from AbstentionBench [18]. The main unanswerable-item probe evaluates four configurations
on GPQA-Abstain and MMLU-Math-Abstain; the expanded GPQA-Abstain evaluation covers all
30 main configurations, including ten matched standard/extended pairs. These probes use fixed task
pools at α = 1, with nonzero injection ratios r ∈ {0.25, 0.5, 0.75, 1.0}.

positive-allocation detection D+ = |U \ S+ |/|U |. The expanded GPQA probe uses listed-ID detection
Dlisted = |U \ Slisted |/|U |, where Slisted contains the problem IDs listed in the plan, including
zero-token entries. Its answerable-item coverage is Clisted = |Slisted \ U |/|P \ U | for pool P , and
selectivity-corrected discrimination is Jlisted = Dlisted + Clisted − 1. Expanded-probe metrics average
pools within each injection ratio and then ratios; coverage and discrimination use ratios containing
answerable items.

Advisory triage is uneven across benchmarks. Advisory efficiency in Figure 1 varies sharply

Binding allocations sharply reduces triage performance. The separation between advisory and

four benchmarks, mean efficiency is ηU = 0.10 under advisory allocations and ηE = −0.60 when

Normalized regret confirms the separation: mean R     eU = 0.50 versus R eE = 0.88. Thus, the same
plans miss approximately one half of oracle value under advisory execution and nearly nine tenths
when their declared allocations are enforced.

Extended reasoning lifts accuracy without consistently lifting triage. Within matched models,
the reference-accuracy curves in Figures 1 and 3 generally rise with extended reasoning. The
corresponding triage scores do not improve uniformly, and higher reference accuracy does not
consistently produce better triage. Increased solving capability therefore does not guarantee better
prospective control: extended reasoning can improve advisory planning while increasing its separation
from enforced performance.

Better allocations improve triage within the same budget. With planned selection, order and total
budget fixed, we rescore single-plan half-budget results. One rule assigns each selected problem its
measured reference cost plus 20%; another gives each an equal share of the budget. Each allocation,
including the margin, is charged against the unchanged shared budget, and scoring stops when the next
allocation cannot be funded. These rules recover 89% and 57% of the matched advisory–enforced
efficiency gap, respectively. These gains without additional budget show that allocation choices
contribute to the deficit. Details appear in Additional Experiments.

Allocation failures persist on problems the model previously solved. To test whether triage fail-
ures persist without reference-unsolved items, we request new half-budget plans for pools containing
only successful Phase-0 completions, using ten API-served configurations across AIME, GPQA, and
LiveCodeBench. Enforced efficiency remains negative in 66 of the 71 pools with valid plans, and
median enforced efficiency is −1.69. Allocation failures thus persist even when every item has a
successful reference completion. Control construction and allocation diagnostics appear in Additional
Experiments.

Behavior across budget pressure. At α = 1, normalized regret is 0.29 under advisory allocations
and 0.82 under enforcement, so substantial losses persist even at the full reference budget. Regret
measures the fraction of reference-solvable value missed, remaining interpretable when the random
and oracle references coincide. The full budget sweep appears in Additional Experiments.

Effective planning also requires recognizing questions that cannot be answered from the supplied
information. Allocating tokens to such questions commits resources that could otherwise support

answerable work. We evaluate this ability by injecting annotated unanswerable items from Abstention-
Bench [18] (GPQA-Abstain and MMLU-Math-Abstain) into the corresponding task pools while hold-
ing pool size fixed. Figure 2 traces four configurations at injection ratios r ∈ {0.25, 0.5, 0.75, 1.0},
using α = 1. Its detection axis D denotes positive-allocation detection D+ : the fraction of injected
items receiving no positive allocation. Planned-token waste W is the fraction of declared token
allocations assigned to those items.

Recognition varies across models. Figure 2 shows substantial differences among the four con-
figurations. Gemini 2.5 Flash maintains relatively high detection across both datasets, while GPT-
OSS 20B’s detection remains low. Qwen 2.5 32B has higher detection than Qwen 3 32B at every
injection ratio on both datasets.

Detection depends on injection ratio and domain. Detection does not decline uniformly as
injection increases. Qwen 2.5 32B’s detection declines monotonically on MMLU-Math-Abstain,
but falls and then partially recovers on GPQA-Abstain. Qwen 3 32B also shows declining detection
as injection increases on MMLU-Math-Abstain. Both Qwen configurations achieve higher average
detection on MMLU-Math-Abstain than on GPQA-Abstain, demonstrating that recognition patterns
also vary across domains.

Models allocate budget even when every item is unanswerable. At full injection, every item
is unanswerable, so every positive allocation goes to an unanswerable item. Gemini and Qwen 2.5
32B continue to leave a substantial fraction of items without allocation, whereas Qwen 3 32B and
GPT-OSS 20B allocate tokens to nearly every item. Thus, some configurations continue committing
resources even when the pool contains no answerable work.

Expanded matched comparisons favor extended reasoning on average. The expanded GPQA
probe measures whether models leave unanswerable items out of their plans. It covers all 30 main
configurations. Across the ten matched models, mean detection increases from 0.26 under standard in-
ference to 0.47 under extended reasoning, with higher detection in eight pairs. Discrimination Jlisted ,
which also accounts for answerable-item coverage, is higher under extended reasoning in all ten.
The broader comparison therefore favors extended reasoning on average, while recognition remains
model-dependent. The matched results and probe definitions appear in Additional Experiments.


6   Conclusion

Deploying language models as autonomous agents that manage a task pool under a shared token
budget requires a capability that single-task accuracy does not capture: prospective metacognitive
control over which problems to attempt, in what order, and with what allocation, committed before
any execution feedback. TRIAGE evaluates this capability by scoring committed plans against an
oracle built from model-specific reference outcomes and token costs.
Across 20 models in 30 inference configurations and four domains, stronger solving capability does
not guarantee better metacognitive control. Extended reasoning generally improves accuracy but
has configuration-dependent effects on triage quality. Triage performance varies substantially across
domains and drops sharply when planned allocations become binding. Allocation counterfactuals
show that the same total budget can support substantially better performance, while failures persist in
pools containing only problems the model previously solved. Matched reasoning-mode comparisons
favor extended reasoning on average for recognizing unanswerable items, with variation across
models. Reliable upfront planning therefore remains an important challenge for resource-efficient
agent deployment.

A    Limitations and Broader Impact
TRIAGE measures prospective resource allocation through a committed task-pool plan. Its design
isolates this capability, while bounding the conclusions that can be drawn from the scores.

Construct and execution model. We use metacognitive control in a functional sense, evaluating
prospective performance judgments through task selection and resource allocation. These behavioral
measurements do not establish equivalence with human metacognition or shared cognitive mecha-
nisms. The planner commits before receiving execution feedback. TRIAGE therefore complements
evaluations of interactive revision and does not measure the full performance of an autonomous
agent. Regimes U and E score the same plan against fixed reference completions: E tests whether
declared allocations cover their recorded costs, rather than generating a new completion under each
allocation. A solver explicitly prompted with a smaller budget can change its strategy, response
length, or correctness. The budget-aware re-solving experiment in Appendix C.10 examines this
distinction, but does not establish equivalence between reference-based scoring and live execution
under hard limits.

Reference measurements and grading. A single successful reference completion does not imply
that a problem is always solvable by the model, and a failed completion does not establish intrinsic
unsolvability. Repeated Phase-0 measurements characterize this variability separately from repeated
planning. Outcomes also depend on answer extraction and grading: HLE free-form answers use
deterministic matching rather than expert semantic judgment, and LiveCodeBench execution can
be sensitive to the fixed timeout and host load. The oracle represents what is achievable under the
recorded outcomes and costs, rather than a bound on all possible future solver samples.

Coverage and inference settings. The results cover four benchmark domains and a finite set
of model configurations. Available-run summaries exclude unparseable outputs, so differences in
parsing coverage can affect comparisons; valid empty plans remain scored. The AIME evaluation
contains only two pools per configuration, making its repeated-planning estimates particularly
variable. Reasoning modes are operational settings exposed by the evaluated checkpoints or API
routes. Reference completions may stop at the configured generation limit, so their token costs need
not reflect the effort required to finish a solution. These settings and coverage are documented in
Appendices B–C.

Resource accounting and external validity. The shared budget represents recorded task-solving
output-token costs. Input tokens, planning overhead, latency, and monetary prices are outside
this budget and could change deployment decisions. Provider-specific accounting is described in
Appendix B.4. The benchmarks consist of publicly available, predominantly English, text-based
problems; we cannot establish that they were absent from model training. Conditioning the oracle
on the same reference measurements makes the comparison model-specific, but does not eliminate
contamination or establish generalization to other workloads, languages, modalities, or task values.

Broader impacts. TRIAGE can help identify unreliable resource commitments before deploying
systems under limited compute. Its results can also be overinterpreted: a strong score on these
workloads does not establish reliable autonomous behavior in consequential settings. Optimizing
directly against a fixed evaluation may improve benchmark-specific strategies without improving
prospective control more broadly. The framework should therefore be used alongside task-level
evaluations and deployment-specific validation, with its resource model and coverage made explicit.

B.4    Output-token accounting

C.2    Plan parsing, scoring coverage, and aggregation

Parsed plans. The deterministic parser first attempts JSON decoding, including extraction from
code fences or surrounding text. The API and repeated-run parser can also retain complete entries
from a truncated array; the repair procedure can wrap a single plan object as a one-entry array.
Non-object entries and IDs outside the pool are discarded. For the main planning scores, the first
entry for a repeated ID is retained. Token counts are converted to non-negative integers; missing or
invalid counts become zero. A successfully parsed empty array is a valid empty plan and is scored,
rather than treated as a missing response. Outputs without a recoverable plan are excluded from the
affected available-pool average. Declared allocations are not rescaled when their sum exceeds the
budget: the specified sequential budget-stop rule determines which entries can be reached.
The parser retains listed problems whose declared allocation is zero. In regime U, these problems
remain eligible to be reached in plan order and are charged their measured reference costs, since
declared allocations are advisory. In regime E, zero-allocation problems are skipped and receive no
value.

Reference coverage. Scoring uses pool IDs with recorded correctness and positive reference cost.
A pool is not scored if it has no reference-matched items. We exclude a pool if fewer than half
of its reference-matched items have both a gradeable outcome and a positive measured token cost.
Unparseable outputs and insufficient reference coverage are missing evaluations; they are distinct
from a valid empty plan, whose achieved value is zero.

Means and variability. For each configuration, benchmark, budget, and planning run, we average
metrics equally over available scored pools. HLE pools are combined across its five retained categories.
Each bar in Figures 1 and 3 is the mean of the available planning-run estimates, and its whisker is

for k ≥ 2. The aggregates in Results average the 120 configuration–benchmark bar means equally.

C.3   Metric boundaries and integer budgets

Efficiency has its random-to-oracle interpretation when Voracle > Vrandom . A small positive gap can
magnify deviations below the random reference, so efficiency is not bounded below by zero. If the
computed gap is non-positive, the implementation records 1 when VM ≥ Voracle and 0 otherwise.
These values represent a boundary convention. This convention also applies to zero-oracle pools.
Normalized regret is computed only when Voracle > 0; zero-oracle pools do not enter regret averages.
When the budget covers the sum of all reference costs, every complete ordering fits under U and the
oracle and random values coincide. Normalized regret reports the fraction of oracle value missed and
remains interpretable at the full reference budget. We therefore report regret at α = 1.
