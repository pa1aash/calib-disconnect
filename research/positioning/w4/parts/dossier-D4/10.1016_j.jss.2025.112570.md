# OPENIA, probing internal representations for code correctness (10.1016/j.jss.2025.112570)
Status: published (Journal of Systems and Software 230, 2025, article 112570; venue per the reference entry in research/notes/251002934-autoprobe-model-agnostic-correctness-assessment-full-text.md, Ref. 28). Source: research/notes/correctness-assessment-of-code-generated-by-large-language-models-using-internal.md (arXiv 2501.12934 HTML, 16,007 words). Text basis: FULL TEXT (arXiv version; journal version not retrieved).
Identity: this DOI is OPENIA (Bui et al.), not AutoProbe; it duplicates the D2 row 2501.12934, so use one verdict.
Measured: a probe (MLP, 128 and 64 units) on the last-token, last-layer hidden state, plus layer and token ablations (Sec 4.3, RQ1 to RQ4).
Models and benchmarks: instruction-tuned DeepSeek Coder 1.3B and 6.7B, Code Llama 7B and 13B, Magicoder 7B; HumanEval, MBPP, DevEval, 10 samples per task (Sec 4.1, 4.2, Table 1).
Findings: "up to a 2X improvement in standalone code generation and a 3X enhancement in repository-specific scenarios" (Abstract); weighted accuracy, precision, recall, F1 (Sec 4.3, Tables 2 and 3).
Leaves open: baselines are LLM-Check, CodeBERT and CodeT5+ classifiers, and zero-shot judges (in-house and o4-mini), not stated confidence, token probability, or sampling agreement; no calibration metrics (L2 question 1, L1).
Breadth:

- base and instruct pairs: instruct only (Sec 4.2)
- post-training stages: not present
