# Uncertainty highlighting in AI code completions (2302.07248)
Status: accepted (ACM TOCHI, DOI 10.1145/3702320; arXiv v3 dated 9 Nov 2024; first posting Feb 2023 per id). Source: research/notes/generation-probabilities-are-not-enough-uncertainty-highlighting-in-ai-code-comp.md. Text basis: FULL TEXT.
Measured: a human-subjects study (N=30) of token highlighting in code completions: none, lowest generation probability, or highest predicted likelihood of a programmer edit (a closed-world "edit model" trained from 9 participants) (Sec 1, Sec 4).
Models and benchmarks: Codex Code Davinci 002, temperature 0.5, one completion per task; three LeetCode tasks (Sec 4).
Findings: "highlighting tokens with the lowest generation probability does not provide any benefit over the baseline condition in which no highlights are shown" (Sec 1); edit-model highlights gave faster completion and more targeted edits (Sec 1, Sec 6).
Leaves open: token-level uncertainty compared by human utility, not by execution-graded localization or calibration; no test-group or requirement confidence (L4 question 1, A11); edit labels are human edits, not execution outcomes.
Breadth:
- confidence families: token generation probability; learned edit-likelihood model
- model families: Codex only
- scales: not reported
- benchmarks: three LeetCode tasks
- base and instruct pairs: not present (searched: base, instruct)
- post-training stages: not present
- reasoning vs non-reasoning: not present
- elicitation formats: highlight thresholds and design probes (shading vs probabilities)
- label source: human edits; unit tests passed and time as outcomes
- label independence: edit model trained on separate participants
- contamination split: not present; Sec 4 says exclusion of the problems from training cannot be guaranteed
- calibration metrics: not present (searched: ECE, calibrat, AUC)
- granularity: token
- causal intervention: human-subject randomized highlight condition, not a model intervention
Bears on: L4 component (A11, token-level confidence as localization): NARROWS lightly, since token-level generation probability has been shown not to help programmers find errors. L1, L2, L3: no effect.
