# Interim report: collapse-proof-training-objective

**Locus question:** Which exact train-time objective for expressed code-confidence provably avoids the disconnect paper's "calibration without discrimination" collapse AND the DCPO gradient-conflict?
**Flavor:** dialectical

## What the corpus already said

The disconnect paper's own diagnosis (query grounding, not a fetched note): the 274-example LoRA-r16 SFT intervention on Qwen2.5-Coder-7B-Instruct cut verbal ECE by 64% but produced "calibration without discrimination" — mean confidence 0.900 on both easy and hard HumanEval problems, distribution collapsed to one bin. This is the failure mode any proposed objective must provably avoid, on top of DCPO's separately-proven accuracy/calibration gradient conflict.

Pre-fetch, the vault held only abstract pages for five of the six key sources. The loci.json rationale (`research/loci.json`) framed the fight as: 260113284 (RLVR worsens overconfidence, SFT calibrates better) + DCPO (gradient conflict for joint objectives) vs. CAPO (discrimination-first AUC surrogate) / Beyond-Binary-Rewards (bounded proper scoring rule) / ORCE (decoupled head) / Rewarding Doubt (log-score RL, single-GPU, AUROC 0.859) — "all clean but QA-only." Digging into full text overturns part of this framing (see below): DCPO is **not** QA-only — it has direct code-domain results, which is the single most important correction this investigation makes.

## What the new sources say

**CAPO** ([[calibration-aware-policy-optimization-for-reasoning-llms]], Wang et al., ACL 2026, arXiv:2604.12632). CAPO proves GRPO's implicit advantage estimator is mathematically an AUC surrogate with φ(t) = −t, which Gao & Zhou's (2012) consistency theorem shows is AUC-*inconsistent* (needs convex, differentiable, non-increasing φ with φ′(0)<0 — linear φ fails). This is a formal reason GRPO-style accuracy-only RL degrades *relative* calibration even as accuracy rises. CAPO's fix, a logistic surrogate φ_τ(t)=log(1+exp(−t/τ)), is AUC-consistent and admits a regret bound. Its own argument for why ECE alone is insufficient reads almost verbatim like our paper's own failure: *"assigning identical confidence (e.g., 0.5) to both correct and incorrect responses perfectly satisfies absolute calibration criteria yet fails to distinguish them."* Swap 0.5 for 0.900 and this is a formal description of the disconnect paper's own collapse. Trained Qwen2.5-Math-1.5B/7B, full fine-tune, 8×A100, 24–48h — **not** single-GPU/LoRA as tested, and **no code-domain evaluation**.

**DCPO** ([[decoupling-reasoning-and-confidence-resurrecting-calibration-in-reinforcement-le]], Ma et al., ICML 2026, arXiv:2603.09117). Proposition 4.2 (Gradient Conflict), proved formally: for an over-confident model where Conf_θ(x) > E_y[R(y)] and confidence-feature φ(y) is positively correlated with reward R(y) (Cov_π(R,φ)>0), the Fisher-metric inner product ⟨∇J_acc, ∇J_cal⟩_{F⁻¹} = −(∂ℓ/∂c)·Cov_π(R(y),φ(y)) is **strictly negative** — i.e. any single coupled objective summing an accuracy term and a calibration term (exactly the shape of RLCR's reward, and structurally the shape of our paper's own joint SFT loss) has provably anti-aligned gradients once the model starts drifting overconfident, which is the generic regime for a code LLM whose pass-rate is already high. DCPO's fix is architectural, not a loss-weight balance: split the response into a reasoning block o_r and a verbalized `<conf>` confidence block o_c, compute *separate* group-relative GRPO advantages A_r (binary correctness) and A_c (confidence reward R_c(o_c) = −|confidence(o_c) − R_IG|, a bounded absolute-error/Brier-like term against a hybrid instance+group execution-pass-rate target R_IG = λ·R̃_G + (1−λ)·R(o_r)), then apply a **masked gradient** so each advantage only touches its own token subset — mechanically preventing the proven conflict rather than trading it off. Theorem 5.1 proves this decoupled estimator is statistically consistent (E[c|q] = E_y[R(y)]) *because* it is optimized independently of the reasoning policy.

Critically, **DCPO evaluates directly on code**: trained on the PrimeIntellect-verifier dataset, evaluated on LiveCodeBench v5, v6, and HumanEval+ with Qwen3-8B (non-thinking), 8×A100, full fine-tune. Exact Table 2 numbers (Acc / ECE / PCE / AUROC):

| Method | LCB-v5 AUROC | LCB-v6 AUROC | HE+ AUROC | HE+ Acc |
|---|---|---|---|---|
| Base (no training) | 0.634 | 0.659 | 0.802 | 0.902 |
| GRPO (accuracy-only RL) | 0.693 | 0.788 | 0.821 | 0.944 |
| ConfClass (post-hoc MLP on GRPO) | 0.685 | 0.772 | 0.839 | 0.944 |
| RLCR (joint Brier reward) | 0.785 | 0.829 | 0.907 | 0.931 |
| **DCPO (decoupled)** | **0.796** | **0.845** | **0.914** | **0.947** |

DCPO beats RLCR on AUROC on all three code benchmarks *and* on accuracy — RLCR pays an accuracy cost (0.267 vs. GRPO/DCPO 0.320/0.314 on LCB-v5) for its calibration gain, exactly the coupled-objective tradeoff DCPO's Prop 4.2 predicts. Ablation (Table 3, math domain, generalizes qualitatively): removing decoupled optimization drops accuracy 60.8→57.3 and roughly doubles ECE (0.128→0.258); removing *instance-level* labels (using only group-averaged correctness) degrades ECE 0.128→0.209 and PCE 0.126→0.229 — i.e., losing per-instance granularity specifically hurts discrimination, which is directly relevant to why a 274-example run with only 3 coarse tiers would starve the model of instance-level gradient signal.

**Rewarding Doubt** ([[rewarding-doubt-a-reinforcement-learning-approach-to-calibrated-confidence-expre]], Bani-Harouni et al., TU Munich, arXiv:2503.02623). Log-scoring-rule RL reward integrated directly into generation (not decoupled), Llama-3-8B-Instruct, 4-bit LoRA, **single NVIDIA A40**, ~7 days for the hardest (multi-answer QAMPARI) setting. On single-answer TriviaQA: ECE 0.0226, **AUROC 0.8592**, beating a "Trained Probe" SFT baseline that gets a *lower* ECE (0.0189) but *lower* AUROC — the paper's own framing is explicitly that ECE alone hides a model that assigns moderate confidence everywhere, and its RL-trained joint signal is more discriminative than the SFT probe despite worse ECE. This is the strongest existing single-GPU-feasible counter-example to "joint objectives always collapse." But it has **zero code evaluation** — all four eval domains (TriviaQA, QAMPARI, MedQA, CommonsenseQA) are factual QA with a single scalar confidence per final answer, no reasoning-chain structure, no execution-verifiable correctness.

**Beyond Binary Rewards / RLCR** ([[beyond-binary-rewards-training-lms-to-reason-about-their-uncertainty]], Damani et al., MIT, arXiv:2507.16806). Reward = correctness − (confidence−correctness)², proven (any bounded proper scoring rule) to have a population optimum that is simultaneously accurate and calibrated. Qwen2.5-7B / Qwen3-8B, 32 rollouts/prompt, A100/H100, full-parameter GRPO — not single-GPU/LoRA as run. No code benchmark (HotpotQA, TriviaQA, SimpleQA, MATH500, GSM8K, CommonsenseQA, GPQA only). The load-bearing new finding here is the **Toy Arm Task collapse experiment**: under an *unbounded* log-scoring rule, the RL policy converges to a degenerate solution — outputting an invalid answer with confidence 0 on nearly every instance, because in a low-signal regime this maximizes expected log-score reward (near-perfect "calibration," 0% accuracy). The *bounded* Brier variant does not collapse this way (34.4% accuracy, ECE 0.02) because the Brier reward is strictly increasing in true correctness probability, so abstention-gaming is suboptimal. This is a *different* collapse mode than our paper's (confidence-value collapse vs. accuracy-collapse-via-reward-gaming) but it establishes that **boundedness of the scoring rule is not a nicety — it is what prevents a specific class of RL-training collapse** under low signal-to-noise, which is a real risk for harder/rarer code problems.

**Balancing Classification and Calibration** ([[balancing-classification-and-calibration-performance-in-decision-making-llms-via]], Yaldiz et al., arXiv:2601.13284). Additive joint loss L = L_GRPO(θ) + λ·L_CE(y_d; θ) applied *only to the final decision token* (pushed toward uniform when the trajectory is wrong, kept one-hot when right) — a token-position decoupling within an otherwise joint loss, distinct from DCPO's advantage-masking. Qwen3-1.7B/4B/8B, **LoRA rank 16, alpha 32**, 4×NVIDIA A100-40GB, ~500 total GPU-hours across all three model sizes — the single most direct LoRA/single-GPU-class feasibility precedent among the six sources. Explicitly names the collapse mode in prose: *"if scores cluster tightly within a narrow range, the confidence signal lacks utility, and the model can be regarded as uncalibrated for practical purposes"* — and shows via reliability diagrams that plain GRPO collapses Qwen3-1.7B confidence to ≈1.0 for nearly everything, exactly analogous to our SFT's collapse to 0.900. Reports **no AUROC anywhere** — ECE and qualitative distribution-spread only, a real evaluation gap relative to CAPO/DCPO/RLCR.

**ORCE** ([[orce-order-aware-alignment-of-verbalized-confidence-in-large-language-models]], Li et al., Stony Brook, arXiv:2605.12446 — already full text in vault pre-fetch). Two-stage decoupled framework: a frozen answer LLM, then a **separate confidence LLM** conditioned on the fixed (x,y) pair, trained via DPO against a Spearman-correlation reward measuring how much a candidate confidence improves the *global* rank correlation between verbalized confidence and an ensemble-based sampling surrogate κ_s(x) = (1/K)Σg(Y_i,y*) — precisely the same n-sample execution-pass-rate signal our paper already computes with AUROC 0.987. Theorem 1 (proved): the population-optimal solution of the Spearman-correlation objective is *any* strictly increasing transform T of the true reliability η(x) — i.e., discrimination-first by construction, since the whole objective only cares about rank-preservation, not absolute values. Empirically on MMLU/DROP/ReClor with Llama-3-8B/Qwen3-8B/Mistral-7B: ORCE beats a matched SFT-on-the-same-surrogate baseline and ConfTuner on ECE and Spearman correlation simultaneously, while preserving answer accuracy exactly (by construction — the answer model is never touched). No code evaluation, no AUROC reported (uses Spearman/AURC/E-AURC instead, which is a reasonable but not identical discrimination proxy).

## Evidence synthesis

Two claims recur across every source that is not our own paper: (1) coupling a single scalar objective across accuracy and confidence tends to produce either an accuracy cost (RLCR/DCPO's Table 2 comparison) or a discrimination cost, and DCPO gives this a formal proof (Prop 4.2) rather than just an empirical pattern; (2) ECE/absolute-calibration alone is a target a degenerate predictor can satisfy — CAPO states this as a formal motivation for why it reports AUC instead of ECE, and it is a near-exact description of what our paper's own SFT run did. The disagreement in the literature is not really "does coupling cause problems" — every source that measures both metrics agrees it does, to varying degrees — the disagreement is over what to DO about it: decouple architecturally (DCPO/ORCE) vs. keep a joint reward but bound it and rely on real-signal domains to avoid degenerate solutions (RLCR/Rewarding Doubt).

### Position A: keep a joint (single-model, single-reward) objective, but make it a bounded proper scoring rule

RLCR and Rewarding Doubt are the strongest cases for this position, and Rewarding Doubt is the only one of the six sources actually validated as single-GPU/LoRA feasible (single A40). Their argument: a bounded proper scoring rule (Brier, or log-scoring rule with abstention penalized/removed) has a *provable* population optimum that is both accurate and calibrated (RLCR's core theorem), and empirically Rewarding Doubt's integrated (non-decoupled) reward gets AUROC 0.859 on TriviaQA — beating a *decoupled* SFT-probe baseline on discrimination even though the probe has lower ECE. This directly rebuts the idea that decoupling is necessary for discrimination: a well-chosen joint reward, in a real (non-adversarial, non-toy) task, does not obviously trigger DCPO's gradient conflict in a way that destroys discrimination, likely because on real problems accuracy and confidence-feature correlation is imperfect enough (unlike DCPO's Prop 4.2 antecedent Conf_θ(x) > E[R(y)], which requires overconfidence *and* positive correlation) that the conflict term stays small in practice. The engineering cost of decoupling — a second model or a second forward pass with masked gradients — is real overhead Position A avoids.

### Position B: decouple the objective/architecture (masked-gradient token blocks or a separate confidence head), and only then optimize a scoring rule or ranking loss

DCPO is the strongest case: it has a formal proof that the conflict is generic to overconfident models with positively-correlated confidence features (which is close to the code-LLM starting condition, since a 7B code model's accuracy is already high and any perplexity/consistency-style feature is essentially always positively correlated with correctness), and — decisively for this specific locus — it is the **only one of the six sources with direct code-domain results**, where it beats the joint-reward baseline (RLCR) on AUROC on all three code benchmarks (0.796 vs 0.785 LCB-v5, 0.845 vs 0.829 LCB-v6, 0.914 vs 0.907 HE+) while also beating it on accuracy. ORCE adds a second, architecturally distinct decoupling strategy (fully separate confidence LLM, not just masked gradients within one model) with a matching population-optimality proof (Theorem 1) and a discrimination-first (rank-only) reward that sidesteps ECE-gaming entirely by construction. Both decoupled approaches also sidestep RLCR's Toy-Arm collapse risk more robustly than a joint reward would, because a degenerate low-confidence-everywhere policy in the confidence *head* cannot help the frozen/separately-optimized answer policy accumulate reward, removing the incentive structure that produced RLCR-Log's collapse.

**Verdict on the tension:** Position B has better evidence specifically for the *code* domain and for the specific failure mode named in this locus (discrimination collapse, not just an accuracy/calibration tradeoff) — DCPO is validated exactly where our paper needs it to be validated, with a formal mechanism that is closer to a proof than an empirical regularity. Position A's advantage (proven single-GPU/LoRA feasibility) is an engineering fact, not a discrimination-quality fact, and is straightforwardly transferable: nothing in DCPO's architecture requires full fine-tuning or 8 GPUs — the masked-gradient mechanism is a training-loop change, not a scale requirement, and 260113284's LoRA-rank-16-on-4×A100-40GB precedent shows a comparable (single-token, not full-block) form of decoupling survives LoRA fine perfectly well. The synthesis is not "pick a side" but "take Position B's architecture and Position A's engineering budget."

## Committed position

The recommended recipe is a **DCPO-style masked-gradient decoupled objective, LoRA-adapted for single-GPU 7B**, trained against the disconnect paper's own continuous execution-pass-rate signal rather than coarse tiers, using a **bounded** proper scoring rule (Brier-style, not log-score) for the confidence-block reward. Concretely: keep Qwen2.5-Coder-7B-Instruct's answer-generation weights frozen or governed only by the reasoning-token advantage stream; append a verbalized `<confidence>` block after each generated solution; warm-start it with SFT on the *n=10-sample execution pass rate already computed for AUROC-0.987* as a continuous [0,1] regression target (not 3 coarse tiers, no new sampling budget required — this labeling infrastructure already exists in the paper); then run a short on-policy GRPO/DPO refinement stage using a masked-gradient split (reasoning-token advantage from binary pass/fail reward; confidence-token advantage from a bounded Brier-style reward against a hybrid instance+group-level pass rate, mirroring DCPO's R_IG) with LoRA rank 16 on the single A100-40GB already available, following 260113284's demonstrated LoRA-decoupling feasibility budget (~100–150 GPU-hours for one 7B model, extrapolated from its ~500 GPU-hours across three model sizes). The specific mechanism this avoids our collapse: our own SFT loss was a single joint objective over a coarse 3-tier target with only 274 examples — structurally exactly the coupled, low-instance-granularity setup that both DCPO's ablation (instance-level labels matter: removing them costs 0.081 ECE / 0.103 PCE) and CAPO's formal argument (a degenerate near-constant predictor trivially satisfies ECE) predict will collapse; switching to continuous instance-level targets removes the "coarse bins → default-bin collapse" failure, and moving the confidence gradient into its own masked token-block removes the "single joint loss → gradient conflict, resolved by the loss regressing toward the easiest-to-satisfy solution (constant near-mean confidence)" failure that Prop 4.2 formally predicts and that our paper's mean-0.900-everywhere outcome exactly matches.

- **Position:** A DCPO-style masked-gradient decoupled objective (separate confidence-token advantage stream, bounded Brier-style reward against a continuous execution-pass-rate target, LoRA-adapted for single-GPU 7B) is the training recipe most likely to make expressed code-confidence discriminative without repeating the disconnect paper's collapse, because it is the only evidenced approach that (a) has direct code-domain AUROC gains over a joint-reward baseline on the same benchmarks and (b) has a formal mechanism (Prop 4.2) that names exactly the failure our joint SFT hit.
- **Confidence:** medium. DCPO's code-domain numbers (AUROC 0.796–0.914 on LiveCodeBench v5/v6/HumanEval+) are real and directly relevant, but were obtained with full-parameter fine-tuning on 8×A100, not LoRA on one GPU — the single-GPU-LoRA feasibility of the *decoupled* architecture specifically is extrapolated from a structurally different paper (260113284's single-token decoupling under LoRA), not directly demonstrated for DCPO's full masked-gradient block-decoupling. If LoRA rank 16 turns out too low-capacity to represent two structurally different objectives (reasoning fidelity vs. calibrated confidence) within one adapter, the recipe could underperform its full-fine-tune analog materially.
- **Boundary conditions:** This holds for execution-verifiable code tasks (unit-test pass/fail gives an unambiguous, cheap, per-instance reward — exactly HumanEval/LiveCodeBench/MBPP's structure) where a continuous n-sample pass-rate target is already computable, as it is in the disconnect paper. It is not evidenced for open-ended code review/explanation confidence, multi-file/repo-level tasks (a different locus, `self-report-vs-external-judge-vs-probe-reversal`, already flags AutoProbe's reversal there), or for problems where sampling n=10 completions per instance is too expensive at scale (this recipe's warm-start reuses labels the paper already has, but any *new* problem set would need the same n=10 sampling investment).
- **What would change this position:** A published ablation showing DCPO's masked-gradient decoupling degrades sharply under LoRA (vs. full fine-tune) on code specifically — that would flip the recommendation toward Rewarding-Doubt-style joint LoRA training, accepting its unproven code transfer as the lesser risk. Alternatively, if a pilot run on HumanEval with the proposed recipe reproduces a collapse (mean confidence pinned near a constant despite continuous targets and decoupling), that would indicate the coarse-tier/joint-loss diagnosis was incomplete and something else (e.g., insufficient RL exploration, KL penalty too tight, or the 7B model's base confidence-expression capacity) is the true bottleneck — in which case ORCE's fully-separate confidence-LLM architecture (stronger decoupling, at 2x inference cost) becomes the fallback.
- **Evidence weight:** 1 paper (DCPO) with direct code-domain AUROC evidence favoring decoupling over joint reward, plus a formal proof (Prop 4.2) of the mechanism; 1 paper (CAPO) with an independent formal argument (AUC-inconsistency of linear surrogates) that converges on the same "ECE alone is gameable by a near-constant predictor" diagnosis without code evaluation; 1 paper (ORCE) with an independent decoupled architecture and a matching population-optimality proof, no code evaluation; 2 papers (Rewarding Doubt, RLCR) providing the strongest counter-evidence (joint objectives can discriminate well, AUROC 0.86 for Rewarding Doubt) but zero code evaluation between them; 1 paper (260113284) providing the best LoRA/single-GPU feasibility precedent but for a different, narrower (single-token) decoupling and no AUROC metric at all. No source in this batch evaluates a decoupled objective under LoRA on code — that is the single largest evidence gap.

## Open questions

- Does DCPO's masked-gradient decoupling survive LoRA adaptation, or does it need the representational capacity of full fine-tuning to keep the two token-block objectives from interfering through shared low-rank parameters? No source tests this directly.
- What AUROC does a *continuous-target, still-joint* SFT (i.e., fixing only the coarse-tier problem from our paper's collapse, without decoupling) achieve? This is the cleanest ablation to isolate "coarse tiers caused the collapse" from "joint objective caused the collapse" and no source in this batch runs it — worth flagging to the label-and-data-feasibility locus investigator, since it is nearly free to test (relabel the existing 274-ish examples with continuous n=10 pass rates before touching RL at all).
- Whether a Brier-style bounded reward is sufficient to avoid RLCR's Toy-Arm-style abstention-collapse on genuinely hard/near-impossible code problems (e.g., LiveCodeBench's hardest tier), where a model might learn to reward-hack by expressing low confidence on everything hard rather than genuinely discriminating within the hard tier.
