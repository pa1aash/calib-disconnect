# Interim report: self-report-vs-external-judge-vs-probe-reversal

**Locus question:** Given AutoProbe's validated three-way reversal (self-report fails everywhere; external LLM-judge wins on simple code ~0.94; internal probe wins on repo-level ~0.82), should the method train the coder's OWN self-report, a DECOUPLED estimator, or ROUTE by complexity?
**Flavor:** dialectical

## What the corpus already said

The width sweep already established the paper's own diagnostic numbers (query grounding, not a fetched note): sampling-based internal confidence AUROC 0.987, token log-probability AUROC 0.668, AST-clustering proxy AUROC 0.689, and verbal self-assessment (1-5 scale) AUROC 0.564 (τ=0.1) / 0.519 (τ=0.8) — a near-total discrimination failure, with 67% of problems assigned max confidence. A 274-example LoRA SFT intervention cut ECE by 64% but collapsed to "calibration without discrimination" (mean confidence 0.900 on both easy and hard problems). The width sweep also flagged [[orce-order-aware-alignment-of-verbalized-confidence-in-large-language-models]] (decoupled confidence LLM), [[model-agnostic-correctness-assessment-for-llm-generated-code-via-dynamic-interna]] (AutoProbe, the reversal source), and [[functional-entropy-predicting-functional-correctness-in-llm-generated-code-with]] as load-bearing for this locus. None of these had been read in full depth before this investigation; I read all three in full plus pulled summary-level numbers on [[conftuner-training-large-language-models-to-express-their-confidence-verbally]], [[sayself-teaching-llms-to-express-confidence-with-self-reflective-rationales]], and [[rewarding-doubt-a-reinforcement-learning-approach-to-calibrated-confidence-expre]] to check whether "self-report fails" is a universal law or an artifact of *untrained* self-report.

## What the new sources say

No new external fetches were needed — the corpus already contained full-text primary sources sufficient to resolve this locus with direct quotes and numbers. I deepened three already-present notes to source-analysis depth (full-body read, not just summary) and cross-checked three adjacent notes' numeric claims.

**[[model-agnostic-correctness-assessment-for-llm-generated-code-via-dynamic-interna]] (AutoProbe)** — the reversal is real but its magnitude is asymmetric, and I want to flag this precisely because the locus framing treats it as symmetric. On independent-unit functionality, averaged across 6 code LLMs (DeepSeek-Coder-1.3B/6.7B, CodeLlama-7B/13B, Magicoder-7B, CodeGemma-7B): External LLM-AJ (o4-mini judging externally) hits accuracy 0.91–0.97 (avg ≈0.94), while AutoProbe (internal hidden-state probe) only reaches 0.63–0.71. That is a 23–34 point gap — a landslide. On repo-level functionality, the reversal is real but far narrower: AutoProbe reaches 0.76–0.87 vs. External LLM-AJ's 0.70–0.87 — a gap of roughly 0–11 points, and on DeepSeek-1.3B the two literally tie (0.87 each). The paper's own explanation: "the performance degradation [of LLM-AJ] can be attributed to the reasoning-based nature of LLM-AJ approaches... repo-level code involves multi-file dependencies, preventing LLMs from explicitly accessing the entire project," whereas representation-based methods "exploit the richer feature patterns of complex code to achieve better robustness" as code gets longer and more structurally distinctive.

Crucially, AutoProbe's **In-house LLM-AJ** condition — the *same* model that generated the code, re-prompted to judge its own output — is the closest analogue to "self-report" in this paper, and it is catastrophic: accuracy 0.27–0.73 across models and settings, frequently *worse* than every other baseline including simple CodeBERT/CodeT5+ classifiers. The paper's own diagnosis: "the same LLM that generates the code is also used to assess its own outputs, making it prone to overconfidence in the correctness of its responses." This is the same overconfidence mechanism the disconnect paper documents (67% max-confidence bin), from an independent codebase, independent models, and independent benchmark family (HumanEval/MBPP/DevEval vs. security benchmarks) — strong convergent validation that *naive, untrained* self-assessment of code fails regardless of elicitation format (Likert scale vs. classification prompt) or task complexity.

**[[functional-entropy-predicting-functional-correctness-in-llm-generated-code-with]] (Functional Entropy)** — corroborates the self-report failure independently, across three languages (Python, Java, SQL) and multiple models (GPT-4o, Gemini-2.5-Pro/Flash/Flash-Lite): free-form "verbalized confidence" (VC) AUROC ranges 0.54–0.80, "inconsistent" per the paper's own language, and the authors explicitly write this is "consistent with prior observations that LLMs tend to express overconfident or inconsistent self-assessments." But the same paper shows a *constrained* self-report variant — P(True), reading the token probability the model assigns to a "True/False" verdict rather than free-text confidence — is markedly stronger and more consistent: 0.82–0.87 on Python/SQL, beating VC by 10–30 points in the same setting, same model, same self-referential structure. This is the single most important data point against a blanket "self-report can't discriminate" reading: the failure mode is tied to the *free-text/Likert elicitation format*, not to the self-referential act of judging one's own output per se.

**[[orce-order-aware-alignment-of-verbalized-confidence-in-large-language-models]] (ORCE)** — the clearest existing decoupled-estimator precedent. Architecture: "an answer LLM produces only the answer, so its parameters are never touched by confidence-alignment updates and answer accuracy is preserved by construction... a separate confidence LLM generates a verbalized confidence conditioned on both the prompt and the previously generated answer." The stated rationale directly targets the disconnect paper's own SFT collapse mechanism: "joint generation conflates two distinct objectives... RL updates intended to recalibrate confidence can inadvertently degrade answer accuracy." Results (QA/reasoning only — MMLU, ReClor, LogiQA — never code): ECE reductions from 0.170→0.025 (LLaMA-3-8B, MMLU), 0.212→0.034 (Qwen3-8B, MMLU), 0.178→0.065 / 0.164→0.044 / 0.468→0.061 (ReClor, three backbones), with Spearman correlation and AURC/E-AURC consistently best-in-class, and answer accuracy "preserved" in every reported setting. Notably ORCE never reports AUROC directly (uses Spearman/AURC/ECE instead), which is a comparability gap against this paper's AUROC-primary framing.

**Cross-check on "does trained self-report ever work?"** — [[conftuner-training-large-language-models-to-express-their-confidence-verbally]] (tokenized Brier score, a proper scoring rule, NO decoupling, NO sampling at train/inference time, single-GPU 7-8B models) reports "up to 54.7% relative improvement in ECE and 14.4% relative improvement in AUROC over the best baseline" on QA — never tested on code. [[rewarding-doubt-a-reinforcement-learning-approach-to-calibrated-confidence-expre]] (RL with a log-scoring-rule reward on a verbalized confidence token, single A40 GPU, joint/non-decoupled) reports TriviaQA AUROC 0.8592, explicitly arguing this beats a lower-ECE "Trained Probe" baseline because ECE alone "can hide a model that assigns moderate confidence everywhere" — a direct rebuttal, from outside this paper's own team, of the "calibration without discrimination" collapse the disconnect paper diagnosed. Both are non-decoupled, same-model, trained self-reports that discriminate well on QA. Neither has been tried on code.

## Evidence synthesis

### Position A: The coder's own self-report can be made discriminative — decoupling is unnecessary if the *objective* (not the architecture) is fixed

The strongest version of this position rests on ConfTuner and Rewarding Doubt: both are joint, single-model, non-decoupled trained self-reports, both single-GPU 7-8B feasible, and both reach AUROC 0.85-0.86 on QA tasks using either a proper scoring rule (tokenized Brier) or a log-scoring RL reward — mechanisms specifically designed so the loss-minimizing policy is provably tied to true conditional correctness probability, unlike the disconnect paper's SFT loss (274 examples, coarse tiers, unclear whether the loss was a proper scoring rule). Rewarding Doubt's authors explicitly show their AUROC-favoring, log-score-trained model *beats* an ECE-favoring SFT "Trained Probe" baseline that quietly collapsed discrimination while looking good on ECE — this is the exact "calibration without discrimination" failure the disconnect paper independently discovered, and it has an independently-validated fix (proper scoring rule / log-score RL replacing the disconnect paper's unspecified joint SFT loss). The mechanism is well-understood and portable: nothing about tokenized Brier score or log-scoring-rule RL is QA-specific: it needs only per-example binary correctness, which for code is *cheaper and more reliable* than for QA (unit-test execution vs. exact-match/LLM-judge labels).

### Position B: Decouple the confidence estimator from the coder, because joint optimization structurally conflicts with answer accuracy

The strongest version of this position rests on ORCE's mechanism argument and on DCPO's documented gradient conflict (from locus 2's territory, cited here for completeness): when a single policy is updated to jointly improve both the generated answer and the reported confidence, "the model cannot distinguish whether the improvement signal pertains to the answer or to the verbalized confidence." ORCE eliminates this by freezing the answer generator entirely and training a separate confidence-only component post-hoc, guaranteeing "preserved... by construction" answer accuracy — a guarantee that a joint objective, however well-designed, cannot offer analytically (only empirically, per run). AutoProbe's In-house LLM-AJ failure (0.27-0.73 accuracy, worse than simple classifiers) is further evidence that even a full separate JUDGING PASS by the same weights, using the same knowledge, still inherits self-serving overconfidence bias when the task is "evaluate what you just wrote" — suggesting the failure may not be purely an objective/loss problem but partly an inherent bias of self-referential judgment, which only true architectural separation (different weights, different training signal, no shared optimization trajectory) can fully rule out.

## Committed position

The evidence does not support treating "self-report fails" as a monolithic finding — it fails specifically when (a) untrained/prompted (In-house LLM-AJ, free-text VC) or (b) trained with a naive/non-proper-scoring joint SFT loss on too little data (the disconnect paper's own 274-example collapse), but it demonstrably succeeds when trained with a proper scoring rule or log-scoring RL reward directly on the SAME model's own output token, as ConfTuner (AUROC +14.4% relative, 0.86-class results) and Rewarding Doubt (AUROC 0.859 on TriviaQA) show on QA — neither of which has been tried on code. Given Priority 1 = novelty and Priority 2 = feasibility, the highest-value, lowest-risk core for this paper is therefore a **same-model, decoupled-optimization self-report**: keep the coder's own weights and prompt-visible identity (preserving the "expressed interface" framing that is this paper's actual contribution, unlike a fully external judge or fully separate confidence model, which would just be porting ORCE/AutoProbe to code — a weaker "X but for code" novelty claim), but decouple the *training/inference stage* the way ORCE does: freeze the generation forward pass, then run a second confidence-only turn (LoRA-adapted, conditioned on the fixed generated code) trained with a proper scoring rule (ConfTuner-style tokenized Brier against execution-pass-rate labels, which the disconnect paper already computes at n=10 samples with zero additional label cost). This directly repairs the disconnect paper's own documented failure mode (joint 274-example SFT collapse) with a mechanism independently validated twice outside this paper's lineage, on the paper's own held-out failure case, at single-GPU 7B scale. The AutoProbe complexity-crossover (Direction D) should be a secondary discussion point, not the headline: the reversal is directionally real (mechanism: reasoning-based external judges lose context on multi-file code; representation-based methods gain signal from longer, more structurally distinctive code) but it is asymmetric (a 23-34 point External-judge win on simple code vs. a 0-11 point AutoProbe win on repo-level code), it concerns post-hoc THIRD-PARTY correctness assessment methods rather than the coder's own trained expressed confidence, and building a repo-level benchmark is a separate, larger feasibility lift than this paper's single-GPU/HumanEval-scope budget supports (per the label-and-data-feasibility locus). Route-by-complexity is a defensible one-paragraph future-work/robustness-check mention (e.g., report whether the trained self-report's AUROC degrades on longer/more complex HumanEval+ problems as an ablation), not a second experimental pillar.

- **Position:** Build a same-model, decoupled-optimization (frozen-generation, second-turn LoRA confidence head) self-report trained with a proper scoring rule against execution-pass-rate labels; do not build a fully separate confidence model (ORCE-style) or a complexity router (AutoProbe-style) as the paper's core.
- **Confidence:** medium-high (65-75%). The QA-domain evidence that trained self-report can discriminate is strong and comes from two independent groups (ConfTuner, Rewarding Doubt) with consistent AUROC ~0.85-0.86 results at matching single-GPU 7-8B scale, and the decoupled-optimization mechanism (ORCE) is independently well-motivated by a documented gradient-conflict problem. What keeps this from being "high" confidence: zero of these three precedents (ConfTuner, Rewarding Doubt, ORCE) has been tested on code, and code correctness is a stricter, more bimodal (compile/pass vs. fail) signal than QA exact-match, which could behave differently under a proper scoring rule loss — this transfer is plausible, not yet demonstrated.
- **Boundary conditions:** This position holds for function-level, independent-unit code generation (HumanEval/MBPP-scale, the disconnect paper's actual scope) where per-example binary pass/fail labels are cheap (unit-test execution, already computed at n=10 in the disconnect paper). It does NOT extend with the same confidence to repo-level/multi-file code, where AutoProbe suggests representation-based (probe) signals gain an edge and reasoning-based (judge or self-report) signals lose context — but this paper's scope doesn't require that extension to be resolved.
- **What would change this position:** If a controlled ablation (same base model, same code benchmark) showed a fully decoupled separate-model confidence estimator (ORCE-style) beating a same-model second-turn LoRA confidence head by a wide AUROC margin specifically on code, that would flip the recommendation toward Position B. Conversely, if the proper-scoring-rule loss reproduced the disconnect paper's own 274-example-style collapse even at larger scale (i.e., collapse is about the domain/task, not the loss), that would undermine the entire Position A mechanism and push toward either the decoupled-model fallback or a pure risk-coverage/selective-generation framing (locus 5's territory).
- **Evidence weight:** 2 strong empirical precedents support trained same-model self-report discriminating well (ConfTuner AUROC +14.4% relative; Rewarding Doubt AUROC 0.859), both on QA only. 1 strong empirical precedent (ORCE) supports decoupling as a safer, accuracy-preserving alternative, also QA-only, with no AUROC reported (comparability gap). 1 primary source (AutoProbe) supports a complexity-conditional reversal between external-judge and internal-probe methods, but this is a different research question (post-hoc third-party assessment) from expressed self-confidence, and the effect size is asymmetric across the two regimes. 1 independent corroboration (Functional Entropy) confirms self-report failure is elicitation-format-dependent (free-text VC weak, constrained P(True) strong), which is the load-bearing mechanistic clue behind Position A's recommendation to fix the objective/format rather than abandon self-report architecture.

## Open questions

- No source in the corpus tests a trained (proper-scoring-rule or RL-log-score) self-report specifically on code — this is the actual experimental gap the recommended method would fill, and it should be flagged as the paper's core novelty claim, not treated as a settled prior result.
- Neither ConfTuner nor Rewarding Doubt report whether their gains hold under a highly skewed/easy-heavy difficulty distribution like HumanEval's (the disconnect paper's own limitation) — worth a targeted check against ConfTuner's full paper (only summary-level was read here) for any difficulty-stratified breakdown.
- AutoProbe's repo-level benchmark (DevEval) and its exact task construction were not investigated in enough depth to assess whether a stripped-down single-GPU version of it could cheaply support a routing ablation as a robustness check — worth a follow-up spin from the label-and-data-feasibility locus if routing is kept even as secondary material.
- ORCE's Spearman/AURC-only reporting (no AUROC) means a like-for-like AUROC comparison between "decoupled" and "same-model second-turn" architectures cannot be constructed purely from corpus text; this would need to be run empirically rather than sourced.
