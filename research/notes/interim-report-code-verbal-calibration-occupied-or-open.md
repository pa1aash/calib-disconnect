# Interim report: code-verbal-calibration-occupied-or-open

**Locus question:** Is "execution-grounded train-time calibration of EXPRESSED confidence for code" genuinely unoccupied, or does RLCM's OOD LiveCodeBench result / Functional Entropy / Rewarding Doubt already collapse it to "X but for code"?
**Flavor:** dialectical

## What the corpus already said

The width sweep had already fetched full text for four of the five key sources under note IDs that differ from what the loci-analyst guessed, plus one more (CSR) that bears directly on the question. [[process-supervision-of-confidence-margin-for-calibrated-llm-reasoning]] (RLCM, JHU, COLM'26) is flagged as "one of the only calibration papers in this set with an actual code-domain result" via OOD transfer from math training. [[multicalibration-for-llm-based-code-generation]] (Campos et al.) is flagged with a pre-written "CRITICAL GAP" note: it "reports ACC and Brier Skill Score / ECE but never reports AUROC." [[calibrating-llms-with-semantic-level-reward]] (CSR, UCSD) is flagged as "the strongest argument AGAINST pursuing a verbalized-confidence interface at all" because it shows verbalized-RL confidence (RLCR, Rewarding Doubt) is token-level unstable. None of these three corpus notes had resolved the specific question this locus asks: does RLCM's LiveCodeBench result, taken on its own terms, already occupy "train-time calibration of expressed code confidence, evaluated by discrimination"?

## What the new sources say

I read RLCM's full text end-to-end (3,096 lines) rather than relying on the corpus summary, specifically hunting for AUROC. **RLCM never reports AUROC anywhere in the paper.** Its evaluation section states it measures three dimensions — "reasoning performance, calibration quality, and confidence discrimination" — but the metrics subsection formally defines only ECE and PCE; "discrimination" is instead characterized qualitatively in Appendix C via confidence-histogram dynamic range (RLCR: quantized, mean .230/median .010; C²GSPG: compressed high-band, mean .819/median .860; RLCM: broad/smooth, mean .572/median .617). On LiveCodeBench specifically, RLCM's numbers are: Base-probe Acc .326/PCE .182/ECE .182; GRPO-probe .380/.004/.130; RLCR-verbal .361/.218/.218; C²GSPG-logits .374/.499/.499; RLCM-probe .389/.050/.051. RLCM wins on accuracy and ECE — but this is a math-trained (GRPO-LEAD, no code in training data) checkpoint evaluated OOD, and the confidence readout is a separately-trained 2-layer MLP probe on hidden states, whose "gradients are only used to update itself and do not backpropagate into the policy" — i.e., not something the model expresses in its own generation, and not trained on code at all. [[process-supervision-of-confidence-margin-for-calibrated-llm-reasoning]]

I found [[functional-entropy-predicting-functional-correctness-in-llm-generated-code-with]] and [[rewarding-doubt-a-reinforcement-learning-approach-to-calibrated-confidence-expre]] already fetched in-vault under different note IDs than the loci-analyst assumed (functional-entropy is arXiv:2605.28500; Rewarding Doubt is arXiv:2503.02623, ICLR 2026). Functional Entropy reports untrained, prompted verbalized confidence AUROC on code at 0.52–0.80 (Python), 0.55–0.62 (Java), 0.54–0.74 (SQL) — "inconsistent... echoing the fragility of verbal self-report" — but only on closed frontier models (GPT-4o/Gemini family) and explicitly excludes open-weight models including Qwen and DeepSeek. Rewarding Doubt is the strongest positive counter-example in the whole corpus: a genuinely verbalized confidence token, trained via log-scoring-rule RL integrated into generation (not a decoupled probe), on Llama-3-8B-Instruct with 4-bit LoRA on a single A40 GPU, hits AUROC=0.8592 on TriviaQA — explicitly argued by the authors to be *more discriminative*, not just better-calibrated, than an SFT "Trained Probe" baseline with lower ECE. But it is "[n]ever tested on code — all evaluation is factual QA." A third already-in-vault paper the fetcher surfaced, `conftuner-training-large-language-models-to-express-their-confidence-verbally` (NUS, NeurIPS 2025, arXiv:2508.18847), is a fourth verbalized-confidence-RL paper (tokenized-Brier-score reward on the confidence token's own logits) reporting both ECE and AUROC — up to 14.4% relative AUROC improvement over SaySelf/LACIE baselines (e.g. HotpotQA AUROC 0.60→0.74–0.79) — but again evaluated only on HotpotQA/GSM8K/TriviaQA/StrategyQA/TruthfulQA, with no code benchmark at all.

I delegated a fetcher to chase three additional threads and it returned four new full-text sources, all newly tagged `locus-code-verbal-calibration-occupied-or-open`:

[[fine-grained-approaches-for-confidence-calibration-of-llms-in-automated-code-rev]] (arXiv:2604.06723, April 2026): local vs. global Platt scaling on fine-grained (not sequence-level) confidence for program repair/vulnerability repair/code refinement across 14 models. This paper does measure discrimination — via Kendall's τ_b and Wasserstein-1 distance between correct/incorrect score distributions, not AUROC (min-token-prob τ_b 0.26–0.45) — but its confidence signals are exclusively internal/logit-derived (min token probability, lowest-K, attention-weighted); nowhere does it verbalize confidence or evaluate code *generation* rather than code *revision*. It also states, of one signal type, "this type of degenerate confidence score lacks the capability of instance-level discrimination, it cannot support decision-making or thresholding" — a direct acknowledgment, from a fourth independent 2026 code-calibration lab, of exactly the discrimination-collapse risk this locus investigates.

[[when-to-answer-and-when-to-defer-a-decision-framework-for-reliable-code-predicti]] (arXiv:2605.19369, ICSE 2026, UT Dallas — Rathnasuriya & Yang): this is a **vision/roadmap paper**, not a completed study — it says so explicitly ("milestones are planned for completion within a 12 month timeframe"). It uses DeepSeek-Coder-7b and CodeLlama-7b on MBPP+, the same model family as our target paper. Its stated empirical finding independently corroborates the target paper's own post-hoc result: "post-hoc calibration techniques often reduce probability misalignment but fail to improve the ranking of predictions by correctness likelihood." Critically, "reward-aware training" and "logit-based behavioral calibration" for *generative* code models are listed under future work, not results — what is reported today is weighted-logistic post-hoc scaling (selective accuracy at 80% coverage) and a logit-based *classification* (defect-prediction) calibrator, neither verbalized nor AUROC-evaluated.

[[asking-is-not-enough-protocol-sensitivity-in-llm-confidence-calibration]] (arXiv:2605.27752, SNU, June 2026): shows the verbalized-vs-token-probability gap is itself sensitive to measurement protocol (answer provenance, conditioning context, token readout) on 4 QA benchmarks — under a default "generated-answer, bare-context" protocol, the gap nearly disappears for Instruct models. QA-only, no code, but relevant as a robustness caution for how the target paper's own 0.668 vs. 0.52–0.56 gap should be reported and defended.

`underspecification-does-not-imply-incoherence-the-risks-of-semantic-collapse-in` (arXiv:2607.01953): not a calibration-training paper at all, but a threat-model paper directly relevant to the target paper's *internal* signal (not this locus's expressed-signal question): sampling-based UQ can converge confidently on a consistent but wrong interpretation under prompt underspecification, affecting 3% of HumanEval, 10–16% of MBPP, and 18–32% of LiveCodeBench items (up to 5.5× under injected ambiguity). Flagged here as a robustness caveat for the eventual paper's internal-signal baseline, not as evidence on occupancy.

## Evidence synthesis

Across the five 2026 code-calibration papers I read at full-text depth (RLCM, Multicalibration, Fine-grained-code-revision, When-to-Defer, plus the target paper's own experiments), **none report AUROC for a code-generation confidence signal produced by a train-time intervention on an expressed/verbalized output.** RLCM comes closest on accuracy+ECE but is math-trained/OOD-transferred and uses a decoupled hidden-state probe, not an expressed output, and never reports AUROC at all. Multicalibration is post-hoc-only and never measures discrimination in any form. Fine-grained-code-revision measures discrimination (τ_b, W1) but only for internal/logit-derived signals on code *revision*, never a verbalized interface, never code *generation*. When-to-Defer is a roadmap that has not yet executed the train-time generative-confidence experiment it proposes. Separately, four verbalized-confidence-RL papers (Rewarding Doubt, ConfTuner, and — per corpus tags — SaySelf/LACIE) prove the *mechanism* (RL reward shaping on a genuinely generated confidence token) can produce AUROC in the 0.74–0.86 range — but every one of them is QA/factual-domain only. Functional Entropy shows untrained verbalized code-confidence tops out around 0.80 on frontier closed models and is both inconsistent and untested on the open-weight family (Qwen/DeepSeek) our target paper actually uses.

### Position A: The space is effectively occupied — RLCM already generalizes best-in-class to code

RLCM trains only on math and still achieves the best accuracy *and* the best ECE/PCE on LiveCodeBench among every calibration-aware baseline tested (GRPO, RLCR-verbal, C²GSPG-logits), and its Appendix C dynamic-range analysis is explicitly offered as evidence of "a more expressive confidence representation" — i.e., an implicit discrimination claim. A reviewer familiar with RLCM could reasonably ask: if a margin-supervised process-reward probe already transfers this well OOD, what does training it natively on code actually buy, beyond an incremental domain match? The mechanism (attach a lightweight probe to intermediate states, reward margin between solvable/unsolvable prefixes) is fully specified and portable; a code-native replication is a comparatively small step, and RLCM's own framing invites exactly that "apply our method to domain X" reading.

### Position B: The space is open — no paper trains an EXPRESSED, code-native, AUROC-validated signal

The RLCM comparison is defeated on architecture, training data, and evaluation rigor simultaneously, not just one axis. Architecturally, RLCM's probe is decoupled from the policy and never backpropagates into it — its gradients "are only used to update itself" — meaning it is structurally an internal signal wearing a thin external head, not something the model expresses in generation. That is precisely the category the target paper's own internal signal (0.987 AUROC) already occupies; RLCM does not touch the expressed-interface failure mode (log-prob 0.668, verbal 0.52–0.56) at all, it sidesteps it. On training data, RLCM never trains on code — LiveCodeBench accuracy of .389 (only marginally above GRPO's .380 and far below the internal-signal ceiling the target paper reports) is consistent with a math-trained probe weakly transferring generic solvability signal, not learning code-specific failure modes. On evaluation, RLCM's own metrics table never operationalizes "discrimination" as AUROC — the paper's discrimination claim rests on a histogram-spread proxy, which is evidence of *expressivity* (using more of the [0,1] range) but not proof of *rank-correlation with correctness*, exactly the ECE-improves/AUROC-degrades conflation the target paper's own post-hoc section is built to diagnose. Multicalibration, Fine-grained-code-revision, and When-to-Defer independently confirm this is a field-wide blind spot: three separate labs studying code calibration in 2026 either skip discrimination measurement entirely or measure it only for internal/logit signals on non-generation tasks — none combine a verbalized interface, native code training, and a rank-based discrimination metric.

## Committed position

The locus is **OPEN**, but only for a precisely-scoped cell: *train-time* (not post-hoc) calibration of a genuinely *expressed* (not probe-decoupled) confidence signal, trained *natively on code* (not OOD-transferred from math), *evaluated via a discrimination metric such as AUROC* (not ECE/accuracy alone) on a generative code benchmark. I verified via direct full-text reading — not abstract skimming — that this exact intersection is empty across all five 2026 code-calibration papers surveyed, and Rewarding Doubt plus ConfTuner supply existence proof that the underlying mechanism (RL/reward-shaped training on a verbalized confidence token) is *capable* of AUROC in the 0.74–0.86 range, just never tried on code. The load-bearing reason RLCM does not collapse this locus: its confidence readout is architecturally a decoupled hidden-state probe that never updates the policy, is never verbalized, is never trained on code, and is never validated by a discrimination metric — it wins on accuracy/ECE via OOD transfer, which is a different (and weaker) claim than "expressed code confidence discriminates." Two mechanistically-adjacent 2026 papers (RLCM, CSR) both deliberately retreat from the verbalized-token interface toward internal/probe/semantic-cluster signals, which is a real headwind — it suggests the field believes verbalized-token training is fragile — but that retreat is itself unresolved for code specifically, since neither paper tested code natively. The recommended pivot: do not compete head-on with "make a single verbalized number more precise"; instead, port Rewarding-Doubt-style log-scoring-rule RL or RLCM-style margin process supervision to code-native execution-verifiable rewards on Qwen2.5-Coder-7B/DeepSeek-Coder-6.7B, decode the trained signal into a genuinely expressed interface (a token, a small confidence-bin vocabulary, or an explicitly user-facing score), and report AUROC on HumanEval/MBPP/LiveCodeBench — making the central empirical bet "does discrimination survive the decode-to-expressed step, or does it reproduce the target paper's own SFT collapse" the headline, since that exact question is untested by every paper surveyed in this locus.

- **Position:** Train-time, code-native, discrimination-validated (AUROC) calibration of an expressed (non-probe) confidence signal for code generation is unoccupied as of this survey; RLCM/Multicalibration/Fine-grained-code-revision/When-to-Defer each fail to occupy it on a different axis (architecture, post-hoc-only, wrong-task/internal-only, not-yet-executed), and Rewarding Doubt/ConfTuner prove the mechanism works elsewhere but never touch code.
- **Confidence:** medium (60–70%). High confidence (~90%) on the narrow factual claim (no paper combines verbalized interface + native code training + rank-discrimination metric); lower confidence on whether a code-native execution-reward version will actually preserve discrimination through the decode step, since this is precisely the failure mode the target paper's own SFT run already hit once, and DCPO-style gradient-conflict concerns (flagged by the sibling "collapse-proof-training-objective" locus) are a live mechanistic threat.
- **Boundary conditions:** Holds specifically for confidence outputs that are decoded/exposed to a user (token, discrete bin, or surfaced score) and evaluated by a rank-discrimination metric (AUROC or equivalent) on generative code benchmarks. Does NOT hold cleanly if "expressed" is defined loosely enough to admit RLCM's linear-probe scalar as an expressed interface — in that reading, RLCM's OOD LiveCodeBench result is a legitimate (if architecturally and empirically weaker) prior claim on this exact cell, and the novelty argument must rest on the native-training + discrimination-reporting distinction rather than a clean "nobody has touched this" claim.
- **What would change this position:** (1) a paper training a code LLM's own expressed output via RL/SFT on code-native execution rewards that reports AUROC >0.75 on a generative code benchmark — would fully occupy the cell; (2) an RLCM successor that decodes its probe into a verbalized token and reports AUROC holds on code — would close the exact gap being proposed as a pivot; (3) the UT Dallas group (When-to-Defer) publishing their "reward-aware training" results with a discrimination metric before the AAAI-27 deadline — a live competitive-timing risk, not a current occupation.
- **Evidence weight:** 9 full-text sources read (RLCM, Functional Entropy, Rewarding Doubt, ConfTuner, Multicalibration, CSR, Fine-grained-code-revision, When-to-Defer, Asking-Is-Not-Enough), plus Underspecification as a tangential robustness caveat. 3 directly confirmed to never report any discrimination metric on code (RLCM, Multicalibration, When-to-Defer); 1 (Fine-grained-code-revision) reports discrimination (τ_b/W1) only for internal, non-verbalized signals on code revision, not generation. 2 confirm the mechanism (reward-shaped RL → discriminative verbalized token) works off-domain (Rewarding Doubt AUROC 0.86, ConfTuner AUROC up to 0.79) — both QA-only. 1 shows untrained verbalized code-confidence tops out ~0.80 on closed frontier models only, inconsistent, and untested on open-weight models (Functional Entropy). 1 independently corroborates the target paper's post-hoc ECE/AUROC conflation on code from a different lab/venue (When-to-Defer, ICSE 2026). 0 papers found occupying the precise train-time + expressed + code-native + discrimination-evaluated cell.

## Open questions

- Does RLCM's margin-reward mechanism even transfer architecturally to code generation, which lacks a natural "intermediate reasoning budget" the way math chain-of-thought does (what counts as a forced-completion checkpoint for a half-written function)? Not resolved by any source read.
- Would a code-native version of Rewarding Doubt's log-scoring-rule RL hit the same QAMPARI-style degradation Rewarding Doubt itself shows on harder multi-answer settings (AUROC drops from 0.86 to 0.69) when applied to harder code benchmarks like LiveCodeBench vs. easier HumanEval?
- Is the UT Dallas "When to Answer and When to Defer" team's 12-month roadmap timeline (started ~May 2026 per arXiv date) likely to produce a competing result before an AAAI-27 submission deadline — worth a targeted search closer to submission time.
- Underspecification/semantic-collapse (arXiv:2607.01953) shows the target paper's own internal sampling signal can fail silently (3–32% of items depending on benchmark) under prompt ambiguity — worth a robustness check in the eventual paper's internal-signal baseline, independent of this locus's occupancy question.
- Did not fetch DCPO, CAPO, or Beyond-Binary-Rewards full text (assigned to the sibling "collapse-proof-training-objective" locus) — their gradient-conflict findings bear directly on whether the proposed pivot's decode-step will actually preserve discrimination; that locus's investigator should be consulted before the mechanism is finalized.
