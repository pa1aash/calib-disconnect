# Interim report: fallback-utility-of-collapsed-confidence

**Locus question:** If the train-time intervention only partially breaks the collapse, does the (still-calibrated) signal retain downstream utility via risk-controlled selective generation, giving a defensible secondary headline?
**Flavor:** technical

## What the corpus already said

The width sweep already flagged this locus as an insurance policy: the loci-analyst rationale explicitly names CIC (uncertainty-aware-abstention) and Task Abstention for Code as the two candidate wrapper mechanisms, and frames the goal as establishing a "floor" if verbal discrimination lands short of ~0.85 AUROC. The base paper's own numbers (`research/query-code-llm-calibration-aaai27-eabf3f.md`) are the ground truth this locus must be reconciled against: sampling-based confidence on HumanEval (164 problems) reaches **ECE 0.059, AUROC 0.987**; the SFT intervention (274 examples, LoRA r=16) reduces verbal ECE by 64% but collapses discrimination — the SFT model assigns **mean confidence 0.900 to both easy and hard problems**, i.e., the expressed distribution degenerates to a single default bin. This is the exact failure mode the fallback must survive.

Corpus notes on the abstention/conformal literature (read via `note show`, no new fetch needed for these) sharpen the candidate mechanisms:
- [[240501563-mitigating-llm-hallucinations-via-conformal-abstention]] (DeepMind, Yadkori et al. 2024) — the founding template: self-consistency signal → conformal threshold → hallucination-rate guarantee, general QA only.
- [[260704430-uncertainty-aware-abstention-in-large-language-models-with-provable-al]] (CIC stub) — generalizes this to *any* monotonically-ordered uncertainty score via Hoeffding/Clopper-Pearson upper-confidence bounds on accepted-answer error; abstract alone gives no numbers.
- [[260517029-task-abstention-for-large-language-models-in-code-generation]] (stub) — multiple-hypothesis-testing abstention grounded in *execution* consistency for code; abstract alone gives no numbers.
- [[251022614-does-in-ide-calibration-of-large-language-models-work-at-scale]] — 24M-interaction, 153-developer deployment study: post-hoc Platt-scaling of a single-pass token confidence does **not**, on average, improve alignment with developer acceptance; developers prefer **non-numerical, color-coded reliability indicators** over numeric confidence scores in-editor.
- [[260321172-entropy-alone-is-insufficient-for-safe-selective-prediction-in-llms]] — a single uncertainty signal (entropy) is unreliable specifically at **low target error rates**, the exact regime relevant to a strict alpha.

The stubs left the load-bearing question open: none of them, in abstract form, gave the actual risk-coverage numbers needed to judge whether the fallback is a defensible headline or vacuous insurance. That gap is what the new fetches close.

## What the new sources say

**[[assessing-correctness-in-llm-based-code-generation-via-uncertainty-estimation]]** (Sharma & David 2025, full text, LiveCodeBench 831 problems, gpt-3.5-turbo-instruct + DeepSeek-R1). This is the closest **code-domain, execution-grounded** precedent in the corpus, and it already reports exact abstention numbers via Table 3: symbolic-execution-equivalence-clustering-based abstention policies (SE-SymbNorm, SE-SymbUniform, CC-Symb) achieve **accuracy 77.8–84.6%, false-positive rate 0.01–0.02%, false-negative rate 11.9–20.3%** across the two models. In their own words: "under these policies, the LLM achieves a false positive rate below 0.02%, effectively ensuring that it never outputs incorrect responses, with false negative rates ranging from 11.9% to 20.3%." Translated into risk-coverage language: **~80–88% coverage at a near-zero (≤0.02%) error-among-accepted rate**, on a harder, more recent code benchmark than HumanEval. Crucially this holds even for the *simplest* variant (CC-Symb, raw symbolic cluster count, discarding the log-prob distribution entirely) — the discriminative power comes from precise equivalence clustering, not the probability channel, which is structurally the same insight as the base paper's own sampling-confidence result (pass-rate over resamples beats log-prob).

**[[260704430-cic-full-text-uncertainty-aware-abstention]]** (CIC, Dong & Shinnou 2026, full text — fetched this session). Tested purely on **general QA** (CommonsenseQA, TriviaQA), 7 LLMs, semantic entropy (10 samples) as the only estimator run end-to-end. At **alpha=0.10** with the Clopper-Pearson bound, coverage/answering-rate ranges **0.52–1.00 on TriviaQA and 0.61–0.87 on CommonsenseQA**, realized error ≈0.086–0.092 (respecting the 1-δ guarantee). At the stricter **alpha=0.05**, the method is frequently **infeasible** — the calibration procedure returns no valid threshold on 34–100 of 100 calibration splits for the weaker models (Vicuna-7B/13B, Qwen2.5-3B). This is the paper's own reported failure mode, not an inference. Calibration-set absolute size N is never stated; only the cal/test *ratio* is shown robust down to 1:9.

**[[260517029-task-abstention-for-large-language-models-in-code-generation-full-text]]** (CODEREFUSER, Zhou et al. 2026, full text — fetched this session). HumanEval + MBPP, 4 open-source code LLMs (DeepSeek-Coder-33B, Qwen2.5-Coder-32B, CodeLlama-7B, WizardCoder-33B). Confirmed **zero-oracle at inference time**: oracle tests are used once, offline, to build calibration ground truth; at deployment the method uses only LLM-generated tests plus execution-consistency clustering. Defaults: alpha=0.2, delta=0.1, k=3, N=64 samples, 60/40 cal/test split. Headline: **26.5-point absolute precision improvement, 11.9-point F1 improvement** over the best baseline. The one directly coverage-like number: on MBPP + Qwen2.5-Coder-32B at alpha=0.2, the method abstains on only **~30% of tasks (~70% coverage)** vs. **>80% abstention (~20% coverage)** for the perplexity baseline at the same risk level — i.e., roughly **3.5x more answers delivered at matched risk**. Note this paper reports Precision/F1 against an oracle-derived label, not FDR/coverage-at-alpha directly, so it is not numerically poolable with CIC without translation — a comparability caveat, not a contradiction.

## Evidence synthesis

Two structurally different but complementary bodies of evidence bound the fallback's realistic target. The **code-domain execution-grounded line** (Sharma & David; CODEREFUSER) shows that when the underlying uncertainty score is built from execution/equivalence信号 rather than from a trained verbal channel, abstention policies land at **~70–88% coverage with near-zero-to-low error among accepted outputs**, and beat log-prob/perplexity baselines by a wide margin (26.5 precision points; ~3.5x coverage at matched risk). The **general-purpose conformal-wrapper line** (CIC, and its DeepMind ancestor) shows the formal machinery — Hoeffding/Clopper-Pearson upper-confidence-bound thresholding with a finite-sample 1-δ guarantee — generalizes to *any* monotonically-ranked score, but its own numbers reveal the failure mode explicitly: **at stringent risk levels (alpha=0.05) and with weaker discriminative signals, the calibration procedure frequently returns no valid threshold at all** (infeasible on up to 100% of splits for the weakest model). Neither line has been run on a signal with AUROC as high as the base paper's 0.987 sampling-confidence, so the two literatures jointly imply a target range rather than a proven point: informally, a CIC-style wrapper applied directly to a near-0.99-AUROC signal should sit closer to the Sharma & David code-domain ceiling (~80–90% coverage at low error) than to CIC's own general-QA numbers, which used a visibly weaker single estimator (10-sample semantic entropy, no execution grounding).

The in-IDE-at-scale study adds an orthogonal but important qualitative constraint: it shows post-hoc rescaling (Platt scaling) of a *poorly-discriminating* single-pass signal does not improve real developer-acceptance alignment at 24M-interaction scale, and that developers prefer **binary/color-coded** reliability cues over numeric confidence in the first place. This matters directly for how the fallback should be framed: a risk-controlled abstain/answer (or traffic-light) decision is not a downgrade from a numeric verbalized confidence — per this deployment evidence it is closer to the format practitioners actually want. That reframes the fallback from "consolation prize" toward "arguably the more deployment-relevant contribution," conditional on the paper being honest that it is decoupling the *communication* problem (still unsolved) from the *action* problem (solvable via conformal wrapping of the untouched internal signal).

The one genuine landmine, flagged by CIC's own failure-mode data and reinforced by Entropy-Alone-Is-Insufficient: **low alpha + small calibration set = infeasibility, not just wider intervals.** HumanEval's 164 problems is a thin calibration pool by CIC's own demonstrated standards (which showed infeasibility even with presumably larger QA calibration pools at alpha=0.05 for weaker models). Given the base paper's signal is much stronger (AUROC 0.987 vs. semantic entropy's unreported-but-implied-weaker discrimination on QA), infeasibility is less likely, but it is not ruled out at n=164, alpha=0.05.

### The mechanism constraint the collapse itself imposes

One thing no source states explicitly, but that follows directly from CIC's own method description, is a **binding constraint on which signal can be wrapped at all.** CIC needs a set of *candidate thresholds* to search over — it needs the uncertainty score to have a spread. The base paper's SFT-collapsed verbal signal assigns **mean confidence 0.900 to both easy and hard problems** — i.e., it has degenerated toward a near-constant value. A near-constant score gives CIC (or any conformal/threshold-based wrapper) almost nothing to search over: there is no meaningful risk-coverage curve to trace when the score barely varies. This means the fallback **cannot** be "take the trained-but-collapsed verbal output and wrap it in CIC" — that inherits the collapse. The fallback must explicitly **bypass the trained verbal signal and wrap the untouched internal sampling-confidence signal** (or an execution-consistency score, à la Sharma & David / CODEREFUSER) directly. This is a load-bearing scoping point for how the paper frames the fallback: it is not "CIC rescues the failed training run," it is "when training the *expressed* channel fails, skip expression and act directly on the *internal* channel via a provable wrapper" — a different, and more defensible, framing.

## Committed position

The fallback is real and publishable-grade, not mere salvage — but only if it is framed correctly and scoped honestly. The concrete pre-registered fallback the paper should report is: a CIC-style (Clopper-Pearson upper-confidence-bound) risk-controlled selective-generation policy built directly on the untouched internal sampling-confidence signal (never on the collapsed SFT verbal output, which lacks the score spread any thresholding method needs), evaluated as a risk-coverage curve at a **pre-registered primary target of alpha=0.10** (where CIC's own general-QA results show feasibility is high even for weak signals) with **alpha=0.05 reported as a stretch goal, and n expanded from HumanEval-164 to HumanEval+MBPP (~400+ problems, inference-only, single-GPU-cheap) as the pre-registered fallback-to-the-fallback if alpha=0.05 is infeasible at n=164** — mirroring CIC's own documented infeasibility failure mode rather than pretending it can't happen. The realistic target to beat, drawn from the two closest code-domain precedents, is **coverage in the 70–90% range at accepted-output error ≤2–5%**: Sharma & David hit 77.8–88% coverage at ≤0.02% error via symbolic-execution clustering on LiveCodeBench, and CODEREFUSER delivers roughly 3.5x more answered tasks than a perplexity baseline at matched alpha=0.2 risk on MBPP. Because the base paper's sampling signal (AUROC 0.987) is a stronger, execution-adjacent discriminator than anything tested inside CIC itself (10-sample semantic entropy on general QA, no code, no execution grounding), I expect the paper's own CIC-wrapped numbers to land at or above the Sharma & David ceiling rather than degrading toward CIC's weaker-signal numbers — but this is an extrapolation across two different literatures, not a replicated result, so it should be reported as a hypothesis to test, not asserted in advance. As a headline in its own right, this fallback is defensible for AAAI-27 (it is a first application of finite-sample risk-controlled selective generation to a near-perfectly-discriminating code-confidence signal, with a concrete, provable, deployment-relevant guarantee, and it aligns with the in-IDE-at-scale finding that developers want binary/graded — not numeric — reliability cues) but it is *not* independently "extremely novel" per the user's Priority-1 bar, because CIC (generic mechanism) and Sharma & David / CODEREFUSER (code-domain execution-grounded abstention) already jointly occupy most of the conceptual space; the paper's marginal contribution in a fallback-only scenario would be "tighter numbers from a better signal, first applied at 7B single-GPU scale, explicitly motivated by a documented expressed/internal disconnect." That is enough to not be a dead paper, but the paper should still lead with whatever partial verbal-discrimination result the training run produces (even a partial win, e.g., AUROC 0.65–0.75, is a genuine contribution) and present the CIC-wrapper result as the secondary, guaranteed-to-land headline, explicitly reframed as "decoupling the action problem from the communication problem" rather than as a rescue of the training result.

- **Position:** The pre-registered fallback headline should be a risk-coverage curve (CIC-style Clopper-Pearson thresholding) built on the raw sampling-confidence signal — never on the collapsed verbal output — targeting ~70–90% coverage at ≤2–5% accepted-output error at alpha=0.10 (primary) / alpha=0.05 (stretch, with a pre-registered calibration-pool-expansion fallback if infeasible); this is publishable-grade insurance but should be positioned as the paper's secondary, not sole, headline.
- **Confidence:** medium. High confidence that the qualitative approach is sound and that the mechanism constraint (collapsed signal cannot be wrapped) is correct; medium confidence on the specific 70–90% coverage number, since it is extrapolated across two different literatures (code-domain execution abstention vs. general-QA CIC) rather than a single directly-measured precedent for "CIC applied to code with AUROC-0.987-level discrimination."
- **Boundary conditions:** This holds specifically for a wrapper applied to a signal with meaningful score spread (the raw sampling/pass-rate confidence, or an execution-consistency score) — it does not hold for the SFT-collapsed verbal output, which has degenerated to a near-constant value and therefore offers no thresholds to search over. It also assumes calibration-set size can be grown beyond HumanEval-164 if needed (true here, since it's inference-only and single-GPU-cheap); it would not hold under a fixed, small, immovable calibration budget.
- **What would change this position:** If a code-domain CIC-style calibration run at alpha=0.05 on HumanEval-164 (or even the expanded HumanEval+MBPP pool) returns infeasible on a large fraction of calibration splits — replicating CIC's own reported weak-model failure mode despite the much stronger AUROC-0.987 signal — that would falsify the "should land near the Sharma & David ceiling" extrapolation and mean the fallback headline must be restricted to alpha=0.10-or-looser, a weaker but still defensible claim. Separately, if AutoProbe's finding that external LLM-judge (0.94 accuracy) beats every internally-computed code-correctness signal generalizes from single-pass classification accuracy to the coverage-at-alpha metric, that would suggest an external-judge-based wrapper might beat the paper's own internal-signal-based wrapper, undercutting the "our internal signal is the star" framing — this is untested and should be flagged as an open comparison, not assumed away.
- **Evidence weight:** 2 code-domain execution-grounded abstention results support strong coverage/low-error numbers (Sharma & David: 77.8–88% coverage at ≤0.02% error; CODEREFUSER: ~3.5x coverage improvement over perplexity baseline at matched risk). 1 general-purpose conformal framework (CIC) supports the mechanism's validity but also supplies the concrete failure-mode evidence (infeasibility at alpha=0.05 for weak signals, 34–100/100 splits). 1 deployment-scale study (in-IDE-at-scale) supports the UX case for a binary/graded fallback over numeric confidence but never tests a sampling-based signal, leaving a direct gap. 1 general-QA study (Entropy-Alone-Insufficient) supports the caution about low-target-error-rate fragility of single signals. No source in the corpus has run a CIC-style wrapper on a code-execution-grounded signal at AUROC ≈0.987 specifically — that exact experiment is the paper's to run and is the load-bearing unknown.

## Open questions

- No source combines "CIC's exact Clopper-Pearson/Hoeffding machinery" with "code + execution-grounded, near-0.99-AUROC signal" — this is precisely the gap the paper would fill; worth confirming no very recent (post-CIC) paper has already closed it before committing.
- CIC's calibration-set absolute size N is never stated in the fetched text (only cal/test ratio) — the paper needs to independently determine what N is required for a non-vacuous Clopper-Pearson bound at alpha=0.05 given HumanEval's 164-problem scale; this is a quick simulation, not a literature question.
- Whether CODEREFUSER's Precision/F1-against-oracle-label framing can be cleanly translated into a coverage-at-alpha number for a true head-to-head comparison remains unresolved from the fetched text.
- Whether AutoProbe's judge-beats-probe result (0.94 vs. internal probes' 0.63–0.77) is an artifact of "simple independent-unit code only" or would also hold against the paper's own repeated-sampling signal (which is not a lightweight probe, and already beats AutoProbe's numbers by a wide margin on its own accuracy axis) is untested.
