# Legacy bundle: frozen historical record

Declared in wave 2 (2026-11-10). The project is being rebuilt as a first submission to TMLR, and
every number in the new paper will be regenerated by a new pipeline. The legacy bundle is kept
unchanged as a historical record of what was written, run, and reported before the rebuild.

## Frozen paths

| Path | What it is |
|------|------------|
| `papers/v1/`, `papers/v2/`, `papers/v3/` | Three manuscript iterations (ICML 2026 style) |
| `src/v1_baseline/`, `src/v2_comprehensive/`, `src/v3_multimodel/`, `src/v4_dprc/` | Legacy code, including the unrun v4 pipeline |
| `results/` | Legacy result files (JSON) |
| `data/` | Legacy data (v4 dry-run labels only) |
| `archives/*.zip` | Manuscript snapshots and the ICML 2026 style kit (contents: `archives/README.md`) |
| `REPRODUCE.md` | Legacy reproduction guide. Its body is frozen; the wave 2 banner at the top is the only post-freeze text, and the whole file is now frozen with it |

`archives/README.md`, `docs/`, and everything outside the table are not frozen.

## Enforcement

The tracked pre-commit hook (`tools/hooks/pre-commit`, check 5) rejects any commit whose staged
changes add, modify, delete, rename, or change the type of a file under a frozen path. New files
belong in new, unfrozen locations. The hook has no override switch. Any future change to the
freeze must edit the hook's `FROZEN_RE` pattern in its own commit, with the reason in the commit
message. Install or refresh the hooks with `tools/hooks/install.sh`.

## Recorded decisions

1. **Mismatches are kept as a record.** The manuscript-versus-result mismatches listed in
   `docs/s1/BUNDLE_MAP.md` section 3.2 are retained deliberately as a record and will not be fixed
   in the legacy files.
2. **No legacy manuscript is the base of the new paper.** The new paper is written fresh;
   `papers/v1` to `papers/v3` are reference material only.
3. **Missing remote artifacts are treated as unbacked.** The GPU-host outputs that wave 1 found
   missing (`docs/s1/BUNDLE_MAP.md` section 3.4: DPO pairs and metrics, `exp3_*` outputs, the trust
   study, `sft_confidence_data.json`, all trained adapters including both `qwen_confidence_sft`
   adapters, `sensitivity_summary.json`, the `exp_v3_multimodel.py` outputs, and run logs) are
   treated as unbacked. Legacy claims that depend only on them have no evidence in this
   repository.
4. **Known documentation errors.** Seven script-to-output attributions in `REPRODUCE.md` section 2
   are wrong; the corrections are in `docs/s1/BUNDLE_MAP.md` section 3.6.
